# 第 6 步：廠商請款辨識（設計，尚未寫程式）

> 小批次線 2026-11-04 起草，給主線、陳軒、Lotion 對齊用。範例全為假資料。
> 一句話：**拍廠商請款單／簽單 → AI 讀出欄位 → 變成「應付草稿」→ 讀不出或對不上的欄位標黃問 Lotion → Lotion 核准才入帳。**

```
入口（三個，沿用現有）                 草稿區                         正式資料
┌─────────────────────┐
│ LINE 收件機器人（照片／PDF）│──┐
├─────────────────────┤  │   ┌──────────────────────┐   核准   ┌──────────────────────────┐
│ FJ 收件匣（lineInbox）   │──┼──▶│ fydata/drafts/<id>             │────────▶│ 分包卡期別 c.periods[]      │
├─────────────────────┤  │   │ type: vendorBill（新類型）      │         │ → 應付 pay<cid>_p<no>（自動）│
│ 智慧收件 smartIntake      │──┘   │ 欄位＋信心度＋對位結果＋黃色題目 │         │ 簽單明細 per.slip（人工／機具）│
└─────────────────────┘      └──────────────────────┘         └──────────────────────────┘
                                         │ 退回 / 刪除                    7d 結案 → 成本歷史 costHist
```

## 一、範圍

| 做 | 不做（另案） |
| :-- | :-- |
| 分包廠商的「請款單」（逐項數量×單價）→ 分包卡新的一期 | 業主端請款（已有） |
| 點工／機具「簽單」（人、工、機具台時）→ 分包卡一期＋簽單明細 | 自動付款、網銀匯款 |
| 廠商發票（只有發票號、金額）→ 對到既有期別、補發票號 | 一般費用發票（智慧收件已有 expense） |
| 租賃請款（月租、日數）→ 租賃卡的一期 | 材料採購發票（own_material 已有） |

## 二、草稿格式（`fydata/drafts/<id>`，新 type：`vendorBill`）

沿用現有草稿外殼 `{id, type, by, byName, at, status, summary, payload}`（規則要在 `database.rules.json` 的 drafts type 白名單加 `vendorBill`；唯讀帳號只能新增自己的 pending，與現在一樣）。

```json
{
  "type": "vendorBill",
  "summary": "範例工程行 11 月請款 3 項 NT$ 128,000（範例案）",
  "payload": {
    "src": { "via": "line|inbox|intake", "inboxId": "…", "file": "範例請款單.jpg", "pages": 1, "url": "（Storage line/inbox/… 或 relay/photos/…）" },
    "kind": "bill | slip | invoice | rent",
    "vendor": { "text": "範例工程行", "match": "範例工程行", "conf": "高" },
    "qid":    { "text": "範例案 B1 擋土", "match": "<報價 id>", "conf": "中", "cands": ["<id1>", "<id2>"] },
    "cid":    { "match": "<分包卡 id>", "conf": "中" },
    "date": { "text": "115/11/25", "iso": "2026-11-25", "conf": "高" },
    "from": "2026-11-01", "to": "2026-11-25",
    "invNo": { "text": "AB-12345678", "conf": "高" },
    "rows": [
      { "text": "H型鋼樁打設 H350 L=12M", "qty": 40, "unit": "支", "up": 900, "amt": 36000,
        "rowId": "<對到的分包列 id>", "rowConf": "高", "upCard": 900, "flags": [] },
      { "text": "鋼索 Ø12", "qty": 300, "unit": "M", "up": 30, "amt": 9000,
        "rowId": null, "rowConf": "無", "flags": ["對不到分包列"] }
    ],
    "slip": [ { "date": "2026-11-03", "who": "技術工", "n": 2, "unit": "工", "up": 3500, "machine": "", "hours": null } ],
    "tot":  { "sub": 128000, "tax": 6400, "total": 134400, "taxMode": "外加|內含|未載", "conf": "高" },
    "ret":  { "pct": 5, "amt": 6400, "conf": "低" },
    "adv":  { "amt": 0 },
    "checks": [ "合計與逐項加總差 0 元", "第 2 項單價與分包卡不同（卡 28、單 30）" ],
    "asks":   [ { "field": "rows[1].rowId", "q": "「鋼索 Ø12」要掛哪一項？", "opts": ["新增分包列", "併入第 3 項", "不計"] } ],
    "ai": { "model": "（_AI_MODEL）", "at": 0, "raw": "（AI 原始回傳，留證據；不含其他廠商資料）" }
  }
}
```

- 每個讀出來的欄位都帶 `conf`（高／中／低／無），比照圖面量測檔：**低、無的欄位標黃，一定要人點過才放行**。
- 對位（`match`／`rowId`）是程式做的，不是 AI 猜的：廠商名用 `_ikSubHit` 同一套規則；專案依廠商在哪幾張得標未結案報價有分包卡來縮小，剩一個就自動選、多個就列 `cands` 讓 Lotion 點；分包列依說明正規化比對＋單位＋單價接近度。
- 敏感資料：草稿在 `fydata/drafts`（管理員與唯讀名冊可讀）。單價、金額屬成本資料，唯讀帳號本來就讀得到 private（v6.0.156 B1），不新增外洩面；但**草稿不得夾帶其他廠商的價格**（AI 原始回傳只留這張單的內容）。

## 三、規則

1. **入口**：
   - LINE 收件：檔名或文字有「請款／簽單／計價」→ 收件匣標「可能是廠商請款」，電腦端（HQ，AI 帳號）跑辨識寫草稿；不在雲端函式裡直接呼叫 AI（費用與錯誤好控管，沿用 HQ 現有流程）。
   - FJ 收件匣：每筆加一顆「辨識成廠商請款」（管理員）。
   - 智慧收件：`_INTAKE_TYPES` 的 `vendor_invoice` 改成兩條路：①對到分包廠商（`_ikSubHit` 有中）→ 走本草稿；②一般廠商 → 照舊應付登錄。
2. **核准才入帳**：草稿階段不碰 `q.costs`、`PAYABLES`。按「核准」＝開該分包卡的「廠商請款期別」視窗（`openSubPeriod`）並預先帶入，**由 Lotion 在原本的視窗按儲存**（`_spSave`），應付照現有 `_syncSubPeriodPayables` 自動產生。不另寫一套算錢的路（背對背、保留款、預付抵扣、超量吸收都沿用現有期別邏輯）。
3. **擋與提醒**：
   - 擋：沒選專案／分包卡、黃色題目沒答完、同一張單（廠商＋發票號，或廠商＋期間＋合計）已入帳過（重複請款）。
   - 提醒不擋：單價與分包卡不同（顯示差多少、要不要改卡價或本期覆寫 `pr.up`）、數量超過合約剩餘（沿用 `FJC.pay.overStat`）、合計與逐項加總不符、稅額不是 5%、背對背條件不符（`_b2bIssues`）。
4. **簽單明細**：點工／機具的逐日人數、工數、機具台時存在該期 `per.slip[]`（隨分包卡、private），期別金額＝Σ 工×單價；7d 結案時 `writeCostHist` 依 `per.slip` 寫入成本歷史（工種／機具的實際單價與用量），給以後單價分析。
5. **證據**：核准後把原檔掛到該期（`per.files[]`，Storage 路徑），應付列「歷程」看得到來源草稿 id 與原檔。
6. **退回**：Lotion 按「退回」寫原因 → 草稿 `status:'rejected'`，LINE 機器人可回覆廠商（要 Lotion 另外決定，見第五節）。

## 四、畫面流程（總覽「AI 草稿」→ 一張草稿）

```
┌ 範例工程行　11/01～11/25 請款　NT$ 134,400（含稅）──────────────┐
│ 專案：[範例案 B1 擋土 ▼]　分包卡：[打設 ▼]　發票號：AB-12345678        │
│ ─────────────────────────────────────────────── │
│ 項目              數量  單位  單價   金額     對到分包列        │
│ H型鋼樁打設 H350   40   支   900   36,000   ✓ 打設 H350       │
│ 鋼索 Ø12  🟨        300  M    30    9,000   🟨 對不到（選一個）  │
│ ─────────────────────────────────────────────── │
│ ⚠ 第 2 項單價與分包卡不同（卡 28、單 30）                         │
│ 原檔（點開放大）　　　　　[退回]　[核准 → 開期別視窗帶入]          │
└──────────────────────────────────────────────┘
```

- 手機版逐列卡片（`_mstack`），不左右滑。
- 核准後草稿 `status:'applied'`、記 `appliedTo:{qid,cid,no}`；期別視窗按取消＝草稿維持 pending（比照 `_draftApplying` 存檔才標已套用）。

## 五、要 Lotion 決定的題目（附建議）

1. **核准後要不要再開期別視窗確認？** 建議：要（一次核對數量、預付抵扣、保留款，再按儲存）。另一案是核准即直接寫入期別，較快但少一道把關。
2. **單價與分包卡不同時預設怎麼辦？** 建議：預設照「分包卡單價」，單據價只顯示差額，Lotion 勾「本期照單據價」才覆寫（`pr.up`）。
3. **對不到分包列的項目？** 建議：三選一（新增分包列／併入某項／不計），不准默默略過。
4. **重複請款判斷鍵？** 建議：①廠商＋發票號；沒有發票號時 ②廠商＋期間＋合計金額；命中就擋，Lotion 可按「確定不是重複」放行並留原因。
5. **退回時要不要自動 LINE 回廠商？** 建議：不要自動，先給 Lotion 一段草稿文字自己傳（對外訊息照豐有語氣，不寫內部字眼）。
6. **誰可以按核准？** 建議：只有管理員（Lotion）；唯讀帳號（HQ）只能建草稿。
7. **簽單（點工）單價來源？** 建議：分包卡上的工種單價優先；卡上沒有就用簽單上的，並標黃。
8. **HQ 辨識失敗（看不清楚、手寫）時？** 建議：仍建草稿，欄位全標「需人工判讀」，原檔附上，不丟掉。

## 七、測試

- 合成樣本（假資料）：一般請款 3 項、含對不到的列、單價不同、超量、重複請款、簽單點工 2 天、只有發票號的補登。
- 冒煙：草稿建立 → 黃色題目沒答不能核准 → 核准開期別視窗並帶入 → 儲存後應付出現、草稿標已套用；重複請款被擋；唯讀帳號看不到核准鈕；手機不左右滑。
- `calc/vbill.js` Node 測試：對位分數、重複判斷、合計檢核。
