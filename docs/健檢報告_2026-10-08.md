## 二、可能的錯誤（建議優先處理）

### 1. 案場細節紀錄表入口已壞（確定）
- `openSiteDet(qid)`（app.js:8470）最後呼叫 `go('sitedet')`，但 `page-sitedet` 頁面 div 與 `ALL_PAGES` 的 `sitedet` 項目在 v6.0.28 已拆除，`site-root` 元素也不存在。
- 仍有兩個入口會呼叫它：施工計畫書步驟列的「案場細節」鈕（app.js:28615）與案場選單（app.js:8481）。按下去不會有任何畫面。
- 相關資料 `q.site`／`q.siteHist` 與 `_sdNorm`／`_sdCalc`／`siteExportPDF`／`matEstFromSite` 函式都還在，只是沒有頁面可編輯。
- 處理選項：(a) 把案場細節做成工程專案或報價編輯內的一個區塊（彈窗）；(b) 恢復頁面；(c) 連同入口一併拆掉。需要您決定。

### 2. 指向不存在元素的 `getElementById`（62 個 id）
這些程式碼執行到時會拿到 null；大多已有 `if(!el)return` 保護，不會報錯，但代表那段功能已經沒有畫面：
- 已拆頁面殘留：`page-projects`／`projects-list`／`proj-sub`（舊專案卡片頁）、`site-root`／`sd-sub`（案場細節）、`sn-intake`（智慧收件）、`adv-search-panel`／`as-*`（進階搜尋）、`dash-ar-card`／`dash-*-count`（舊總覽統計卡）、`exbody`／`extotal`（舊費用表）、`qbadge2`／`invbadge`／`invbadge3`／`contractbadge`（舊側欄徽章）、`inv-claim-type`。
- 單價分析舊欄位：`up-site-s1-lbl`…`up-pc-dia-wrap`、`up-prev-*`、`upa-hist-*`（約 20 個，對應下方「無人呼叫」的 `upa*` 系列函式，屬同一批舊 UI）。
- 得標視窗專案獎金欄位 `award-ref-*`／`award-comm-preview`（v6.0.29 已移除 HTML，程式碼仍讀取，已有找不到就不動的保護）。
- 動態 id 誤判（實際存在，可忽略）：`pj-body-sched`、`pj-sec-close`、`wk-f-*`、`mrent-total`、`mtrans-amt`、`qc-item`。

### 3. 空 catch（164 處）
不會造成錯誤，但吞掉例外後無法在錯誤日誌看到。約六成在 v6.0.25 以後的模組（材料、應付、報表）。建議統一改成 `catch(e){_err('位置',e);}`，一次性機械替換即可。

### 4. 覆寫鏈的風險
- `_syncSubPeriodPayables` 被宣告 2 次並包 3 層（v6.0.38 轉提前放款、v6.0.39 抵扣上限、v6.0.44 自我修復）。每次呼叫會依序跑完四段邏輯，彼此透過 `_healBusy` 防遞迴。目前可運作，但任何一層改動都要想到其他三層。建議合併成一個函式。
- `renderMat6`／`renderRfq`／`_healthRows` 各包 2 層，同樣可合併。

1. **先決定案場細節的去留**（二-1），這是目前唯一確定壞掉的功能。
2. 刪除確定無入口的舊 UI 殘留（單價分析舊欄位、計價頁廠商動作、進階搜尋、舊專案頁、舊總覽卡）：約 60 個函式＋對應 id，風險低，冒煙測試可驗。

4. 空 catch 機械替換成 `_err`。
5. CAD 圖庫的 660 行舊版圖碼與 44 個未用圖函式：最後處理，需全部工法出圖檢核。
6. 同步更新 CLAUDE.md（模組地圖改成「模組 → 函式 → 區塊」對照表，歷史註記另存）。

以上任一項動手前都會先列出影響清單，改完跑 538 項冒煙測試再上線。
