# 伺服器每日備份：還原演練（只在測試專案做，約 20 分鐘）

**一句話：把測試專案某一天的伺服器備份，寫回測試專案的資料庫，再對筆數；對得上就代表真的出事時救得回來。**

```
Storage 備份檔（每個節點一個檔）→ 下載 → tools/backup-restore-prep.js 拆檔 → firebase database:set 寫回測試專案 → test.html 對筆數
```

> 只能對 **fj-system-test**（測試專案）做。指令最後都有 `--project fj-system-test`，不要改成正式專案。

## 前置（一次）
- 電腦要有 Firebase 指令（`firebase --version` 有版本號）並已登入（`firebase login`）。
- 測試專案已部署 `dailyServerBackup`，而且至少跑過一次（主控台 › Functions › 紀錄看得到「[備份] 完成」）。沒跑過可以在 Google Cloud 主控台 › Cloud Scheduler 找到這支排程按「強制執行」。

## 步驟
1. **先記下現在的筆數**（約 2 分鐘）：開 https://jhchen0911.github.io/FJ-system/test.html 登入 → 經營報表 › 其他報表 › 資料健檢，抄下最上面「報價 N・請款單 N・合約 N・應付 N」。
2. **下載備份**（約 5 分鐘）：Firebase 主控台（測試專案）› Storage › `fydata/backups/server/daily/<最新日期>/`，把裡面所有 `.json` 下載到同一個資料夾，例如 `C:\FJ-restore\2026-11-05\`。
3. **拆檔**（約 1 分鐘）：在 FJ-system 資料夾開終端機：
   ```
   node tools/backup-restore-prep.js C:\FJ-restore\2026-11-05
   ```
   會印出「備份當下筆數」和要執行的寫回指令。
4. **寫回測試專案**（約 5 分鐘）：把上一步印出來的 `firebase database:set … --project fj-system-test -f` 指令一行一行貼上執行。
5. **對筆數**（約 3 分鐘）：test.html 重新整理兩次 → 資料健檢最上面的筆數，要等於第 3 步印的「備份當下筆數」（報價 quotes、請款單 invoices、合約 contracts、應付 payables）。
6. 截圖第 3 步的輸出和第 5 步的畫面，傳給陳軒。

## 對不上怎麼辦
- 備份之後測試專案又有人新增資料：以第 3 步印的「備份當下筆數」為準。
- 差很多：不要再動，截圖給陳軒，FJ 對話查原因。
