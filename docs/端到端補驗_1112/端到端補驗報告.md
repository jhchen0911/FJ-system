## 發現的問題

1. **刪除「已付一部分」的廠商期別，應付變孤兒、還在待付（嚴重度：高）**
   - 現象：第 3 期應付 8,978 先付 1,000，再到分包卡刪除第 3 期。確認視窗寫「對應的應付帳款會一併移除」，結果期別刪了，應付 `paycE1_p3` 因為有付款紀錄被鎖住留下：狀態待付、餘額 7,978，還出現在「付包商款待核准」，分包卡未付金額（`_subStat.unpaid`）也是 7,978。
   - 重現：段① 8-4、8-5（`payMarkPaid` 付 1,000 → `delSubPeriod('cE1',3)` → `syncCostToPayable`）。
   - 影響：已經不存在的期別還要付 7,978；照畫面付款就會多付。
   - 建議：`delSubPeriod` 的擋法從 `p.status==='paid'` 改成「已付或部分已付」（例如 `_payPaidHard(p)||_payPartial(p)`），提示先撤銷付款；或刪除時把剩下未付的部分作廢（`voidAt`）。
2. **技師計算書 AI 沒讀到的數量被當成 0（嚴重度：高）**
   - 現象：AI 回 `qty:null`（沒讀到），`_sdocCalcSet` 用 `_aiNum(it.qty)` 轉，`_aiNum(null)` 回 0 不是 null，所以存成 0。卡片顯示「中間樁 0 支、差 -20、金額 -60,000」，沒有出現「沒讀到」；差異從 1 項變 2 項，金額從 +20,000 變 -40,000。按確認後，改單草稿多一條「中間樁打設 數量改成 0」。
   - 重現：段② 1-3、4-1～4-3、4-6。
   - 影響：改單草稿要再確認一次才會真的改報價，所以不會直接改錯；但卡片數字是錯的，Lotion 照卡片判斷容易誤會，改單卡沒細看就會把報價數量改成 0（本例少 60,000 未稅）。
   - 建議：`_sdocCalcSet` 改成 `var v=(it.qty==null||it.qty==='')?NaN:_aiNum(it.qty);`。結算書 AI（`_stlAi*`）如果用一樣的寫法，請一起看。
3. **期別改小到低於已付金額，系統直接把應付標成已付（嚴重度：中）**
   - 現象：第 2 期含稅 17,955 先付 10,000，再把數量從 20 改成 5（含稅應付 4,489）。存檔沒有警告，應付自動變「已付」、`overPaid`＝5,511；提示只寫「應付 NT$ 4,489」。修改視窗也沒寫這期已付多少。
   - 重現：段① 8-1～8-3。
   - 影響：多付 5,511 只在應付卡上用一行小紅字「付款紀錄多付」提醒，容易漏掉，沒人追回或抵下期。
   - 建議：`_spSave` 存檔前，如果這期應付有付款紀錄、新金額又低於已付合計，就跳確認（要寫原因）；修改視窗上方顯示「這期已付 X」。
4. **拍板卡被擋下時，原因提示馬上被「沒有完成，這張還留著」蓋掉（嚴重度：中）**
   - 現象：`toast()` 一次只留一則。`_vbConfirm` 先提示「沒寫放行原因，不能確認」再回 false，`decAct` 接著提示「沒有完成，這張還留著」，原因一閃就不見。計算書卡「要登入才能建改單草稿」也一樣被蓋掉。
   - 重現：段① 6-3／6-3b、段② 4-5。
   - 影響：流程沒錯，但使用者不知道為什麼不能確認。
   - 建議：`decAct` 在 `done===false` 時，如果 ok() 已經提示過原因就不要再蓋（例如 ok 回 `{ok:false,why}`，或比對最後一則 toast 的時間）。
5. **版次從檔名猜錯：樓層代號「R2F」被當成第 2 版（嚴重度：低）**
   - 現象：`B1F_R2F平面配置.pdf` 猜成 v2（來源：檔名），跟上一份 v2 撞號。
   - 重現：段② 1-4。
   - 影響：歸檔卡要確認，可以手動改（2-4 驗過），不會直接寫錯。
   - 建議：`_sdocVerGuess` 第三條正則的 `(?!\d)` 改成 `(?![\dF])`（接 F 的不算版次）。
6. **本機模式草稿永遠不會標「已套用」（嚴重度：低，只影響測試／離線）**
   - 現象：`_draftMark` 沒有 `_fbDb` 時直接回 false。離線時廠商請款存好期別，草稿還是 pending；再按一次確認會走「已入帳」那條路，不會多開一期（6-6 驗過），所以不會重複算錢。
   - 建議：維持現狀即可；有需要再在提示說明「離線，草稿狀態等連線後再更新」。
7. **觀察（不算錯，請 Lotion 定口徑）**
   - 廠商請款卡片的明細沒有應付到期日，要按確認、到期別視窗才看得到（1-4b）。視窗、期別 `due`、應付 `date`、存檔提示四處一致（2-1、2-2、5-2）。如果希望拍板前就看到放款日，可以在卡片明細加一行。
   - 付包商款核對會把「業主還沒請款」也算成差異（3-1：日報＝廠商＝40／100，業主 0 → 2 項差異，待辦寫「數量有差異」）。開了業主請款單後就變相符（3-1b）。如果口徑是「付包商款不等業主」（Lotion 10/21），這一項也許該從「差異」改成「資訊」。
