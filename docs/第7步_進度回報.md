## 【交接】派工板：兩台裝置同時改同一案的取捨（分支 `claude/step7-dispatch`，審查 B3）

**現況**：派工存在專案紀錄 `p.dispatch[日期]`。專案紀錄是「一筆一筆同步、修改時間新者勝」，所以兩台裝置在同一個下午改**同一個專案**（例如工務按確認、Lotion 同時在改這案的送審文件或排程），比較晚存的那台會整筆蓋掉另一台的改動。

```
工務手機：確認明天派工 ─┐  p.dispatch[11/12]
                          ├─ 同一筆專案紀錄 → 晚存的贏
Lotion 電腦：改送審文件 ─┘  p.docs
```

**為什麼這一版先接受**：
- 派工是「每天重排」的資料：被蓋掉的那天，明天派工卡會因為 `p.dispatch[明天]` 是空的再出現一次，工務重按確認就補回來，不會靜靜消失。
- 不含金額，算錢只看隔天送出的日報。
- 真的會撞到的情況少：派工在下午 3 點後才出卡，同一案同一時間有人改別的欄位的機率低。

**被蓋掉的會是另一邊**：如果是派工蓋掉送審文件、排程這類欄位，那邊就不會自己再出現，這是比較需要注意的方向。

**之後要改的話（建議做法）**：把派工搬出專案紀錄，改成獨立的一般資料集 `fydata/shared/dispatch/<日期>/<報價 id>`，一天一案一筆、逐筆同步，就不會跟專案的其他欄位互蓋。要改：規則加一個節點、`_SYNC_COLLS`／逐筆同步清單、`_dpMap`／`_dpSave` 改讀寫新位置、舊的 `p.dispatch` 一次性搬過去。估半天到一天，等 7c 專案資料集（送審文件、排程）真的有多人同時在用再做。
