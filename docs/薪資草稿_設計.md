# 薪資草稿（需求書 #19）設計（2026-11-11，小批次線）

> **11/11 更新：Lotion 定案做完整版（Q1～Q7），陳軒定整合 4 題，v6.0.235 實作；實際做法見 `docs/版本紀錄.md` v6.0.235。下面是當初的評估，留作紀錄。**

## 一句話

每月 1 日，系統用「日報出工紀錄＋人員薪資設定」先算好上個月的薪資條草稿，今天頁出一張「○月薪資草稿 N 人，合計 NT$ …」的拍板卡，Lotion 看明細按確認才產生正式薪資條和應付。

## 現在已經有的（不用重做）

| 部分 | 現有功能 |
|---|---|
| 人員薪資設定 | 帳務 › 薪資 `hrEdit`：月薪或日薪、津貼、勞健保自付與公司負擔（`HR`，private） |
| 薪資條計算 | `calc/payroll.js` 的 `FJC.hr.slip`（應發、應扣、實發、公司負擔） |
| 產生薪資條 | `psGenerate`（按一下，替在職且有設定薪資的人產生本月薪資條） |
| 薪資→應付 | `_hrSyncPayables`（應付 id `pay_ps_`，勞健保 `pay_ins_`） |

## 要新做的

1. **出工天數從日報來**（日薪的人）：
   - 讀各案 `q.dailyLogs[].workers`，以及日報裡的人員名單，數出每個人上個月出工幾天。
   - 同一天出現在兩個工地，只算 1 天；半天另外計。
   - 月薪的人不用數天數。
2. **草稿卡 `payDraft`**（每月 1～5 日出卡，管理員才看得到）：
   - 明細列每個人：出工天數（附來源工地和日期）、底薪、津貼、勞健保、實發，以及跟上個月的差多少。
   - 上個月有領、這個月沒有出工紀錄的人，標黃色。
   - 確認：走原本的 `psGenerate` 產生正式薪資條，天數用草稿算的。
   - 退回：這個月改成手動產生。
   - 修改：打開帳務 › 薪資頁。
3. **只算，不付款**：付款照原本的應付流程走，草稿不碰付款狀態。

## 前提與風險

- **目前沒有自己的工人**（現場都是分包），所以日薪出工天數這一段，現在沒有資料可算。
- 月薪的辦公室人員本來就能用 `psGenerate` 一鍵產生，草稿卡能幫上的只有「提醒每月要產生」和「跟上月比對」。
- 日報裡的人員名單還不是固定格式。要先定出工紀錄的格式，才能準確數出天數。這件可以跟進場前人員辦證的人員名單（分包卡 `c.crew`）一起設計。

## 建議

現在先不做完整版。改做一張每月 1 日的提醒卡：「○月薪資條還沒產生」，按確認就跑原本的 `psGenerate`，大約半天工作量。等有自己的工人、日報有固定的出工名單，再做出工天數的部分。
