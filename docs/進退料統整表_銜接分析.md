## 第一部分：給 Lotion 的白話版

### 一句結論

**簽收單拍照、AI 讀單、存進日報、倉庫台帳、租料批次這五樣現在都有，只是各自分開、要管理員一張一張按「帶入」。這次要補的是中間那本「進退料簿」：每一趟車記一筆，工務按確認，後面的台帳、租金、租賃商對帳、業主逾期租金都由系統自己去改。**
最大的難題是「工務看得到、改得到，但看不到錢」。做法是把一筆拆成兩半存：**沒有錢的一半放大家都能讀的地方，有錢的一半放只有 Lotion 能讀的地方**，兩半用同一個編號對起來。

### 資料怎麼流

```
 工務拍簽收單
      │
      ▼
 AI 讀單（現有：智慧收件 delivery_slip）
      │  讀不出的欄位標黃
      ▼
 ┌──────────────────────────────┐
 │ 首頁卡片「簽收單待確認」          │   工務、Lotion 都看得到
 │ [確認] [退回] [修改]             │   （卡片上沒有任何金額）
 └──────────────┬───────────────┘
                │ 確認
                ▼
 ┌──────────────────────────────┐        ┌───────────────────────┐
 │ 進退料簿（每趟一筆，新）          │ ─同編號─▶│ 金額那一半（只給 Lotion）    │
 │ 日期／方向／料／支數／車號／照片   │        │ 運費／租金單價／計租起訖     │
 │ 工務可讀可寫                     │        │ 賠償／吊車費／同車分攤       │
 └───┬──────────┬──────────┬────┘        └───────────────────────┘
     │自有料     │租賃料      │轉場（A 案退、B 案進，一筆寫兩案）
     ▼          ▼           ▼
 公司自有料台帳   租料批次      兩案各自的台帳／租料批次
 （倉庫少、工地多；│
  歸倉只加「可用」）├──▶ 租金成本（施工成本）
                 ├──▶ 租賃商請款核對（第 6 步）：支數×天數×單價，差多少標出來
                 ├──▶ 業主逾期租金（請款單）
                 └──▶ 日期差太多、數字對不上 → 首頁提醒卡
 結案 ──▶ 單價庫（實際租期、每趟運費、損耗率、吊車費）──▶ 下次報價用
```

### 現在有什麼、缺什麼（一張表看完）

| 需求 | 現在 | 缺 |
| :-- | :-- | :-- |

| 加碼 4 防錯檢查 | ⚠️ 只有「同日同車號算一趟」 | 進退加總、重複登錄、運輸請款趟數對不上 |
| 加碼 5 車型建議 | ❌ | 依距離、數量建議；運費行情累積後比價 |

### 工作量（白話）

大概分 **6 包**，前 2 包是地基，一定要先做：

```
A 地基：新資料表＋舊資料搬家（M）
  └─ B 首頁卡片＋AI 多讀欄位（M）
       ├─ C 自動改自有料台帳（M）
       ├─ D 租金／租賃商對帳／業主逾期租金（L，D2 等第 6 步）
       ├─ E 防錯檢查與提醒卡（S～M）
       └─ F 結案回寫單價庫、租或買、閒置、車型建議（L，分兩次）
```

第 6 步（廠商請款辨識）只卡 **D2 租賃商請款核對**這一小塊：要等第 6 步的草稿做好，對帳結果才有地方顯示。其他都可以先做。

**重要發現**

1. **業主逾期租金現在跟材料進退場無關**：`rentStatus` 用的是工項的租期天數＋日報的「拔除」進度，不看 `q.mat.rents`。所以「進退料簿 → 業主逾期租金」不是接一條線而已，要決定口徑（疑問 2）。
2. **台帳只能在管理員裝置改**：`MAT_LEDGER` 在 private，工務的瀏覽器讀不到也寫不了。所以「工務按確認 → 台帳自動更新」一定是：工務寫 shared 的確認紀錄 → **管理員裝置（或雲端程式）看到後套用**。這跟現在 `matLoc` 由管理員裝置產生是同一個模式。
3. **工務在智慧收件其實已經「確認」過一次**：AI 讀完會跳出可修改的欄位，按存檔才進日報。新卡片要決定是否取代這一步（疑問 1）。
4. **AI 草稿區工務讀不到**（`fydata/drafts` 規則），所以簽收單卡片**不能**套用第 6 步的 `vendorBill` 草稿外殼，要另開工務可寫的節點。
5. 租料單價只有一個 `rt.rate`（$/M/月），**沒有「16M 以上另一段單價」**，也沒有「每片每月」的計價單位。
6. `_m6SlipM` 用 `len×qty` 算 M 數；鋼板樁類「每片」計價時 M 數不適用，要分單位。

| 4 | 防錯：進退加總對不起來、同一張單重複登錄、運輸請款趟數與簽收單張數不符 | `_m6SlipTrips` 算趟數 | ①每案每規格 進−退−短少−損壞＝在場量，結案時≠0 出卡；②重複鍵＝照片 hash 或（日期＋車號＋單號＋品項）；③運輸公司請款（第 6 步）趟數 vs 進退料簿趟數 |
| 5 | 車型建議（遠距離叫平板，不叫吊板）＋運費行情比價 | 無；地區係數在 `UPA_COST_DB`（只乘搬運費） | 規則表：距離（疑問 6，先用「縣市＋是否跨區」判斷）、支數 → 建議車型；`matHist` 累積 `freight` 後，顯示同地區同車型的近期均價與本次差異 |

**為什麼這樣拆**

- 工務只碰 shared，規則可以白名單欄位：`matMoves/$id` 下只允許上面那些子鍵，`$other: .validate false`，**連不小心帶金額都寫不進去**。
- 已確認（`st:'ok'`）的紀錄，規則只讓管理員改（`data.child('st').val() !== 'ok' || isAdmin`），工務改錯要按「修改」走回 draft 前由 Lotion 處理，避免確認後被改掉卻沒重新套用台帳。
- 金額跟「套用到哪幾列台帳」放 private，工務的瀏覽器永遠不會下載到。
- 每筆同時記 `qid`（報價 id）；專案資料集 `PROJECTS`（`p_`＋主報價 id，`_prjOfQ`）可由 qid 反查，不另存專案 id，追加報價的料掛主約。
- 唯讀帳號（陳軒）可讀 private（v6.0.156 逐項放行），要不要讓它讀 `matMoveFin` 在規則逐項清單裡決定；預設比照 `matLedger`。
- 不放進報價記錄 `q` 裡：轉場要同時屬於兩案，獨立集合用 `qid/fromQid/toQid` 篩，比寫兩份好對帳；也不會讓報價記錄越來越肥。

**套用器（台帳自動更新）跑在哪**

- 建議：**管理員裝置**在私有資料下載完後跑一次 `_mvApplyAll()`（比照 `_salesCommBoot`），之後每次收到 shared 更新再跑。冪等：`matMoveFin[mvId].applied.sig` 與目前內容簽章相同就跳過；內容變了先「反套用」再重套。
- 管理員好幾天沒開 FJ 時台帳會慢；之後可把同一份 `calc/matmove.js` 搬到雲端程式（functions/ops，管理員權限）每天跑一次。**第一版先做裝置端**，因為台帳現在是整包同步，雲端寫整包容易跟裝置衝突。
- 套不上的（例：倉庫沒有同規格同長度庫存、退場找不到工地上的那批）不硬套，出首頁卡給 Lotion。

**規則要改（`database.rules.json`，改完要到主控台發布）**

1. `fydata/shared/matMoves`：整個集合只有管理員能整包寫；`$id` 逐筆放行 access 名單（同 `shared/quotes/$qid`），唯讀名冊不可寫；子鍵白名單＋已確認只限管理員改。
2. `fydata/private/matMoveFin`：沿用 private 既有規則（不用新加）。
3. 不動 `fydata/drafts`（工務本來就不能寫）。

**舊資料一次性遷移 `_mvMigrate()`（旗標 `P.__mvMig=1`，只在管理員裝置跑）**

1. 每張舊 `slips`（含 `done`）→ 建一筆 `matMoves`：`dir` 對照 out→`out` 自有、back→`in`… 注意方向是以「工地」為主：倉庫→工地＝進場、工地→倉庫＝退場；rentIn/rentOut 同理；`other` 建 `st:'draft'` 等人補。`src.slipId` 記回原單，避免重複遷移。
2. **已勾「已登錄」的舊單 → `st:'ok'`，但 `applied` 直接標成「舊資料、已人工處理」，不再動台帳**（否則同一批料會被扣兩次）。沒勾的 → `st:'draft'`，出現在首頁卡片等確認。
3. 現有租料批次 `batches` 若沒有對到任何簽收單：**不補建**進退料紀錄（避免憑空生資料），只在新表上顯示「舊批次（無簽收單）」。
4. 舊 `slips` 欄位一律保留；v5／舊版裝置讀不到新集合也不會壞（新集合是新增的鍵）。
5. 混用期：舊版裝置的「帶入」按鈕仍能用，但會變成雙軌；上線後第 7 步換畫面時把「帶入」拿掉（按鈕盤點表第 5 題已決定改首頁卡片）。

### 5. 要問 Lotion 的疑問（附建議答案）

1. **工務拍照時，AI 讀完要不要先讓工務在手機上改一次，還是直接進首頁卡片？**
   建議：直接進首頁卡片，拍照那一步不再跳出修改畫面，只看到「已收到，待確認」。這樣只有一個地方確認，不會改兩次。

2. **業主逾期租金，要看哪一天算「料已經退了」？** 現在系統看日報裡的「拔除」進度；新的進退料簿有每一趟的退場日。
   建議：**業主請款仍照合約（日報拔除進度）算**，進退料簿的退場日只拿來比對，差超過設定天數出提醒。因為業主合約認的是拔除，不是料車離場；料留在工地但已拔除，不該向業主收。

3. **「租料已經用完、還沒退場」要怎麼判斷？**
   建議：該工項日報已記「拔除完成」（或階段完工），但進退料簿這批料還在場超過 3 天 → 出卡片「問業主、安排退料」。天數可在參數改。

4. **簽收單日期和租賃商計租日期，差幾天要提醒？**
   建議：差 **1 天以上**就提醒（租金按天算，多 1 天就是多付），卡片上直接寫「可能多算 N 天、約 NT$ X」，金額只給 Lotion 看。

5. **工務按「確認」之後，台帳就立刻自動改嗎？還是 Lotion 要再看一次？**
   建議：自有料照需求**確認就自動改**，但只有三種情況改成卡片等 Lotion：倉庫找不到同規格庫存、退場支數比工地上多、歸倉狀況是「要修／報廢」。其他不打擾。

6. **車型建議的「遠距離」怎麼算？**
   建議：先用簡單規則：**跨縣市（倉庫所在縣市以外）算遠，建議平板車**；同縣市且需要現場卸貨才建議吊板。等運費資料累積 3 個月後，再改成依實際運費行情比價。需要 Lotion 告訴我們倉庫在哪個縣市（可寫在參數）。
