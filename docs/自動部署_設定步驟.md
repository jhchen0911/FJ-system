# Firebase 自動部署：一次性設定步驟（給 Lotion）

設好之後，雲端程式（functions）和資料庫規則（database.rules.json）推上 `main` 就會自動部署。
不用再開 PowerShell 打 `firebase deploy`，也不用再到主控台貼規則。
Storage 規則（storage.rules）照舊到主控台貼上。

```
FJ 主線推上 main ──▶ GitHub「Firebase 自動部署」
                       │ 先看這次改到哪些檔
                       ├─ functions／calc 有改 ──▶ 部署雲端程式
                       ├─ database.rules.json 有改 ──▶ 發布資料庫規則
                       └─ 都沒改 ──▶ 什麼都不做
                       （用「部署專用帳號」的鑰匙，鑰匙鎖在 GitHub 保險箱）
```

## 這次要做的三件事

1. 在 Google Cloud 建一個「部署專用帳號」（服務帳號），只給部署要用的權限。
2. 幫它產生一把鑰匙（一個 JSON 檔），從電腦直接存進 GitHub 保險箱（Secret）。存好後把鑰匙檔丟進資源回收筒。
3. 在對話裡說「上線」，主線推上自動部署，第一次會自動演練一次。

鑰匙檔的內容**不要貼到任何對話裡**，也不要傳 LINE、不要放到雲端硬碟。

## 一、建立部署專用帳號（網頁）

1. 用 jhchen0911@gmail.com 開 https://console.cloud.google.com/iam-admin/serviceaccounts?project=jhchen-aed9a
2. 上方確認專案是 **jhchen-aed9a**。不是的話，點左上角專案名稱，選 jhchen-aed9a。
3. 點上方「**+ 建立服務帳戶**」（CREATE SERVICE ACCOUNT）。
4. 「服務帳戶名稱」填 `github-deploy`。下面的 ID 會自動帶出 `github-deploy`。說明可填「GitHub 自動部署 FJ functions 與資料庫規則」。按「**建立並繼續**」。
5. 「將專案存取權授予這個服務帳戶」：點「選取角色」，在搜尋框打下面的名稱，點選。每加完一個就按「**+ 新增其他角色**」再加下一個，總共 9 個：

   | 搜尋框打這個 | 要點的角色 | 為什麼要 |
   |---|---|---|
   | Cloud Functions 管理員 | Cloud Functions 管理員（Cloud Functions Admin） | 更新雲端程式；新的網址型程式要設公開 |
   | 服務帳戶使用者 | 服務帳戶使用者（Service Account User） | 雲端程式用預設帳號執行，部署時要代它操作 |
   | Cloud Scheduler 管理員 | Cloud Scheduler 管理員（Cloud Scheduler Admin） | 每天定時跑的程式（健檢、提醒、備份） |
   | Eventarc 開發人員 | Eventarc 開發人員（Eventarc Developer） | 資料庫有變動就觸發的程式（名冊、推播） |
   | Cloud Run 管理員 | Cloud Run 管理員（Cloud Run Admin） | 第二代雲端程式跑在 Cloud Run 上 |
   | Secret Manager 檢視者 | Secret Manager 檢視者（Secret Manager Viewer） | 確認 LINE／AI 金鑰存在（只看得到名稱，看不到內容） |
   | Firebase Realtime Database 管理員 | Firebase Realtime Database 管理員（Firebase Realtime Database Admin） | 發布資料庫規則 |
   | Firebase 檢視者 | Firebase 檢視者（Firebase Viewer） | 讀專案基本設定 |
   | Service Usage 消費者 | Service Usage 消費者（Service Usage Consumer） | 確認需要的 Google 服務都已開啟 |

6. 9 個都加完，按「**繼續**」，再按「**完成**」。

這 9 個權限只夠「部署」，不能直接看金鑰內容、改帳號權限或刪專案。

但要老實說：能部署雲端程式＝能放任何程式上去跑，能發布規則＝能把資料庫的門打開。所以這把鑰匙**等同高權限**，要當成公司大門鑰匙看待：只放 GitHub 保險箱、不貼對話、不存檔；懷疑外流就照最後一節「鑰匙要換或收回」馬上刪掉。

## 二、產生鑰匙並存進 GitHub（網頁＋PowerShell）

### 網頁：下載鑰匙

1. 在服務帳戶清單點 **github-deploy@jhchen-aed9a.iam.gserviceaccount.com**。
2. 上方分頁點「**金鑰**」（KEYS）。
3. 點「**新增金鑰**」→「**建立新的金鑰**」→ 選「**JSON**」→「**建立**」。
4. 瀏覽器會下載一個 `jhchen-aed9a-xxxxxxxxxxxx.json` 到「下載」資料夾。不用打開它。

### PowerShell：存進 GitHub 保險箱

① 開新的 PowerShell（開始 → 打 PowerShell → Enter）。

② 進下載資料夾：

```
cd $HOME\Downloads
```

③ 確認只有一個鑰匙檔（應該只看到一行 `jhchen-aed9a-….json`）：

```
Get-ChildItem jhchen-aed9a-*.json
```

看到兩行以上，就把舊的那個先丟進資源回收筒，或截圖給陳軒。

④ 確認 GitHub CLI 已經登入（看到 `Logged in to github.com account jhchen0911` 就對了）：

```
& "C:\Program Files\GitHub CLI\gh.exe" auth status
```

沒登入的話，先跑下面這行，照畫面選 GitHub.com → HTTPS → 用瀏覽器登入：

```
& "C:\Program Files\GitHub CLI\gh.exe" auth login
```

⑤ 把鑰匙存進 FJ-system 的保險箱，名稱 `FIREBASE_DEPLOY_SA`（成功會出現 `✓ Set Actions secret FIREBASE_DEPLOY_SA for jhchen0911/FJ-system`）：

```
Get-Content (Get-ChildItem jhchen-aed9a-*.json).FullName -Raw | & "C:\Program Files\GitHub CLI\gh.exe" secret set FIREBASE_DEPLOY_SA --repo jhchen0911/FJ-system
```

⑥ 確認保險箱裡有它（看到 `FIREBASE_DEPLOY_SA` 和今天的日期）：

```
& "C:\Program Files\GitHub CLI\gh.exe" secret list --repo jhchen0911/FJ-system
```

⑦ 把鑰匙檔丟進資源回收筒（GitHub 已經存好，電腦上不留）：

```
Add-Type -AssemblyName Microsoft.VisualBasic; Get-ChildItem jhchen-aed9a-*.json | ForEach-Object { [Microsoft.VisualBasic.FileIO.FileSystem]::DeleteFile($_.FullName, 'OnlyErrorDialogs', 'SendToRecycleBin') }
```

⑧ 確認下載資料夾已經沒有鑰匙檔（沒有任何輸出就對了）：

```
Get-ChildItem jhchen-aed9a-*.json
```

⑨ 鑰匙檔現在在資源回收筒。打開桌面的「資源回收筒」，對 `jhchen-aed9a-….json` 按右鍵 →「刪除」，把這一個檔真的清掉（只刪它，其他檔不用動）。

## 二之一、設定舊映像自動清除（PowerShell，一次就好）

雲端程式每部署一次會留一份舊映像，不清會慢慢多收一點錢。自動部署的帳號沒有這個權限，所以由你的帳號設一次。

① 進 FJ 資料夾：

```
cd C:\Users\jhche\Agent\my-agent\400_Project\FJ-system
```

② 設定舊映像保留 1 天（問你要不要繼續，按 Y 再 Enter）：

```
firebase functions:artifacts:setpolicy --location asia-southeast1 --project jhchen-aed9a
```

看到 `Successfully` 或「已經設定過」的訊息就好。出現紅字就截圖給陳軒，不影響後面的步驟。

## 三、說「上線」＋第一次演練

在主線對話說「上線」。主線把自動部署推上 `main`，這次推送改到了 `firebase.json`，所以會自動跑一次完整演練：

- 發布資料庫規則：內容跟 11/06 22:26 你貼上的那份一樣。之後如果你在主控台手動改過規則，這次會被 GitHub 上的版本蓋掉；沒改過就不用管。
- 部署全部雲端程式：程式只多了一行註解，行為不變。

主線會盯著結果，綠燈或紅燈都會回報。紅燈多半是權限少一個，主線會說要補哪個角色，你照第一節的方法補上（服務帳戶頁 → IAM → 編輯 github-deploy → 新增角色），之後主線再跑一次就好。

其他會紅燈、要你處理的情況（主線會說是哪一種）：
- 雲端上有、程式裡已經拿掉的雲端程式：自動部署**不會自己刪**，會停下來紅燈，由主線給你一行刪除指令。
- 之後新增一把新的金鑰（例如新的外部服務）：第一次部署要多一個「Secret Manager 管理員」權限，或由你在電腦手動部署那一次。

## 之後怎麼運作

- 主線或小批次線推上 `main` 時，有改雲端程式或資料庫規則就自動部署。推上 main 之前一樣要你說「上線」。
- 你電腦上的 firebase 如果手動部署時說看不懂 `disallowLegacyRuntimeConfig`，先跑 `npm install -g firebase-tools` 更新再部署。
- 想手動重跑：GitHub → FJ-system → Actions → 左邊「Firebase 自動部署」→ 右邊「Run workflow」→ 選 functions／database／both。
- 要停用：GitHub → FJ-system → Actions → 「Firebase 自動部署」→ 右上「…」→ Disable workflow。停用後照舊在電腦手動部署。
- 鑰匙要換或收回：Google Cloud 服務帳戶頁 → github-deploy → 金鑰 → 刪掉舊的。要換就再做一次第二節。
