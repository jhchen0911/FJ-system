## 1. 一句結論

**可以補，而且 V2 的原始內容很可能還在 FJ 裡**：那份「11/03 16:34 非正式快照」幾乎可以確定就是 10/27 寄出的 V2（舊版「還原」功能自動留的備份）。做法是一次性把它升成正式「版 2（10/27，已送業主）」，現在的「版 2（11/03）」改號成「版 3」，正在編輯的那份改成「版 4」，V4 之後照一般流程送出就會封存。

```
現在 FJ 顯示                       補登之後
─────────────────────────          ─────────────────────────────────
現行（編輯中） V3  1,857,713   →   現行（編輯中） V4  （套用 −30,000 改單後 1,826,213）
版 2 正式  11/03  1,857,713    →   版 3 正式  11/03  1,857,713   ← 只改號碼，內容不動
（存檔）   11/03 16:34 快照    →   版 2 正式  10/27  1,846,713   ← 新增一筆正式版（已送業主）
                                   （存檔）   11/03 16:34 快照   ← 原樣保留，不刪
版 1 正式  10/25  1,950,585    →   版 1 正式  10/25  1,950,585   ← 不動
另一張 115110401「第二份報價，未採用」→ 只拿來對照；補登完成後怎麼處理見第 5 節
```

為什麼不能直接手動改：版次紀錄在跨裝置同步時是「各台裝置的紀錄聯集、同一筆以存檔時間認人」，**改既有那一筆的號碼不會傳到別台，別台還會把舊號碼傳回雲端蓋回來**（第 3.4 節）。所以要先上一小段程式，讓每台裝置都照同一條「更正規則」自己改。

## 3. 一次性「補登歷史版次」設計

### 3.1 白話流程（Lotion 看這段就好）

```
① 先備份        ② 陳軒送一張卡片         ③ Lotion 在總覽「AI 草稿」打開卡片
（匯出全部資料）  「補登 115102501 V2」 →   看前後對照、三個數字都對 → 按「套用」
                                             數字不對 → 卡片自己擋住，不能套用
④ 系統自動：存還原前備份 → 新增正式版 2 → 舊版 2 改成版 3 → 編輯中改成版 4
            → 詢價單、請款單、變更草稿裡記的版號一起改 → 上傳
⑤ 另一台裝置重新整理兩次 → 看到一樣的版次清單（驗收）
⑥ 之後照平常：套用 −30,000 改單 → 匯出 PDF「送出並封存」→ 成為 V4
```

不加新按鈕：入口是既有的「AI 草稿」卡片（總覽待辦 → `openDrafts`），和 AI 改單草稿同一套。

### 3.2 補登前要先驗證（任何一項不對就停，不套用）

用 11/03 16:34 那筆快照（以下稱「來源」）做檢查，115110401 只當第二份對照：

| # | 檢查 | 標準 |
|---|---|---|
| 1 | 來源屬於這張報價 | `snapshot.id===q.id`、`snapshot.code==='115102501'`、`formal` 與 `pre` 都不是 true |
| 2 | 報價日 | `snapshot.date==='2026-10-27'` |
| 3 | 列數 | 非分項標題（`!it.sec`）的工項列 = 18；另外把「備用單價」（`_isSpare`）列數也列出來給 Lotion 看 |
| 4 | 未稅 | **用工項重新算**（同 `calcT` 1101：Σ qty×price，跳過 sec 與備用單價）= 1,758,774 |
| 5 | 稅額 | `Math.round(1,758,774×5%)` = 87,939（注意：10/27 存的 `snapshot.t.tax` 可能是 87,938.7，因為稅額四捨五入到元是 v6.0.152（11/03）才改的，**以重算為準，不要只看存的 t**） |
| 6 | 含稅 | 未稅＋稅額 = 1,846,713 |

### 3.3 套用時做的事（技術）

**做法核心：把更正寫成一條「規則」存在報價記錄上，每台裝置自己照規則改，而不是只改本機那幾筆紀錄。**

```js
q.verFix = [{
  id: 'vf_115102501_v2',                 // 冪等鍵：已存在就不再做
  at, by,                                // 套用時間、管理員 email
  insert: { savedAt: SRC.savedAt + 1,    // 新正式版的身分（不能跟來源同一個 savedAt，見風險 3）
            src: SRC.savedAt, ver: 2,
            date: '2026-10-27',
            note: '送出 PDF 115/10/27（補登 115/11/0X）' },
  shiftFrom: SRC.savedAt,                // savedAt 晚於這個、ver ≥ 2 的正式版次一律 +1
  verTo: 4,                              // q.ver 至少要是這個（現行 3 → 4）
  before: { qVer: 3, entries: [{savedAt, ver, snapVer}], rfqs: {rid: quoteVer}, chg: {...}, invs: {invId: quoteVer} },
  undone: false
}]
```

套用步驟（`_qvfApply`，全部在一次存檔內完成）：

1. **備份**（任何一步失敗就整個取消）
   - 下載一個 JSON：`{q, Q_HISTORY[qid], qHistSens[qid], 相關請款單, 草稿}`，檔名 `補登版次備份_115102501_<時間>.json`；同時寫本機 `fy_qvf_bak_<qid>`。
   - `saveQVersion(qid, q, {pre:true})` 存一份「還原前備份」（與 v6.0.148 同一套，永久保留）；`saveQHistory()` 回傳 false（空間滿）就取消。
2. 寫 `q.verFix` 規則（含 `before` 原值，供復原）。
3. 呼叫 `_qhApplyFix(qid)`：
   - 新增正式版：`{savedAt: SRC.savedAt+1, by, formal:true, ver:2, note, backfill:{fixId, src}, snapshot: 深拷貝(SRC.snapshot) 且 snapshot.ver=2}`。**依 savedAt 插到正確位置**（不能用 `unshift`，否則 `_qLastFormal` 39934 會把它當成最新正式版，送出時的「內容相同不重複封存」就比錯版）。
   - `savedAt > shiftFrom`、`formal`、`ver ≥ 2` 的每一筆：`ver` 與 `snapshot.ver` +1（目前只有那一筆 2→3）。
   - `q.ver = max(q.ver, verTo)`。
4. 改其他地方的版號（規則：**舊號 ≥ 3 → +1；舊號 = 2 且建立時間晚於 SRC.savedAt → 3；其餘不變**）：
   - `q.rfqs[].quoteVer`（建立時間用 `r.ts`，沒有就 `r.date`）、`r.chg.from／to`、`r.chgLog[]`、`q.costs[].chgLog[]`，改完 `r.mt=Date.now()`。
   - 這張報價的請款單 `inv.quoteVer`、`it._qRetired`，每張改完 `_touch(inv)`。
   - 沒記 `quoteVer` 的舊詢價單不用改：`rfqBaseVer` 用建立時間推定，新版 2 的 savedAt 落在正確位置，推出來的號碼自然對。
5. `_touch(q)`、`persist()`、`saveQHistory()`、`_immediateUpload()`。
6. 草稿標已套用 `_draftMark(id,'applied')`、`logActivity('報價','補登版次：115102501 V2（10/27）；原 V2→V3、編輯中 V3→V4')`。
7. 開「歷史版本」視窗給 Lotion 看結果。

**冪等**：`_qhApplyFix` 每次都照規則算「應該長怎樣」再改（新版已存在就不再加；號碼已經是新的就不再 +1——用 `before.entries` 記的原號判斷，不是看現值再 +1）。跑 1 次和跑 10 次結果一樣。

**`_qhApplyFix` 要在這些地方都跑一次**（這是要上程式的原因）：開頁讀本機後（27752 之後）、雲端合併後（10311 之後）、匯入備份後（5425）、私有資料補回後（10568）。有改到才 `saveQHistory()`。

**復原**（不加按鈕，主控台函式 `qVerFixUndo(qid, fixId)`，一樣先備份）：把規則標 `undone:true`、`_touch(q)`；`_qhApplyFix` 看到 undone 就把號碼照 `before` 還原、**把補登那筆隱藏**（不能真的刪：聯集合併會從別台裝置帶回來，所以用規則隱藏）、q.ver 還原（若之後又進版過，只扣回 1）。

**入口（不加新按鈕）**：
- 唯讀帳號（陳軒／HQ）在主控台跑 `fyQuoteVerBackfill({qid, src: 16:34 那筆的 savedAt, ver:2, date:'2026-10-27', expect:{rows:18, sub:1758774, tax:87939, total:1846713}})`，和 `fyQuoteChange`（40603）同一套：本機先試算、對不上就不送 → `_draftPush('qverfix', payload, summary)`。
- 草稿規則不用改：`fydata/drafts/$id/type` 只驗是字串、`payload` 只驗有子節點（database.rules.json），新增 `srcSavedAt`、`expect` 欄位可以寫入。
- Lotion 在總覽 → AI 草稿 → 卡片 `_qvfOpen(id)`：前後對照表（版次清單改前／改後、三個數字、與 115110401 的差異、會改到的詢價單／請款單／變更草稿清單）→「套用」／「先不要」。
- `_DRAFT_T` 加 `qverfix:'補登版次'`；`openDrafts` 的分派（38602 附近）加一行。

### 3.4 風險與對策

| # | 風險 | 對策 |
|---|---|---|
| 1 | **版次紀錄聯集合併**：同一個 savedAt 本機優先（10003）。只改號碼的話，別台裝置保留舊號，而且 `qHistory` 是整包上傳，別台下一次存檔就把舊號傳回雲端蓋掉 | 規則存在 `q.verFix`（報價記錄逐筆同步、`_mt` 新者勝，會傳到每一台），每台合併後都重跑 `_qhApplyFix`。**程式要先上線、所有裝置重新整理兩次之後，才套用補登** |
| 2 | 別台裝置還開著舊報價（`q.ver=3`）又存檔，`q.ver` 被打回 3 | `_qhApplyFix` 同時把 `q.ver` 補到 ≥ `verTo`（並 `_touch`）；套用時請 Lotion 確認其他裝置沒開著這張報價；套用後在第二台裝置驗收 |
| 3 | 新版次用和來源同一個 savedAt，會被合併當成「同一筆」，別台永遠看不到 formal 旗標 | 新版次用 `SRC.savedAt+1`，套用前檢查這個值沒被用過 |
| 4 | 新版次的成本欄位（private）沒跟上 | 只在私有資料已下載的管理員裝置套用（`_QH_SENS!==null`）；`_qhSensMap` 會從本機完整快照產生 `qHistSens[qid][新 savedAt]` |
| 5 | 待套用的 AI 改單草稿（baseVer=3） | **不改草稿**。補登後 `_qchgOpen` 會顯示「草稿依據 V3，目前是 V4（V3 已封存）：會改在 V4」——這句剛好就是事實；另外會出現「草稿建立後這張報價被改過」，改單是逐列用說明文字對，對得上就能套。順序：**先補登，再套 −30,000 改單，再送出** |
| 6 | 補登前就先把 V4 送出了（又多封存一版） | 規則是「savedAt 晚於來源的正式版一律 +1」，多一版也照樣對；但建議先補登再送 |

### 4.2 修正提案（不加任何按鈕）

1. **每次匯出都留紀錄**：`_qSendGate` 所有出口（送出並封存／只匯出／內容相同／唯讀帳號）在 `q.sendLog` 記 `{at, by, what, sig(雜湊), mode, ver}`，最多 50 筆。「只匯出」另外把當下內容存成一筆 `sent:true` 的非正式紀錄（`_qhKeep` 把 `sent` 也算永久保留），內容不會再像 V2 一樣只能靠運氣找回來。
2. **還原時自動補封存**：`restoreQVersion` 檢查「目前內容」的簽章（`_qSendSig` 39933）是否等於某次匯出、但不等於任何正式版 → 確認視窗的文字改成「這份內容 10/27 匯出過、還沒封存，還原前會先封存成 V{n}」，按確認就先 `_qBumpDo` 再還原。只改既有視窗的文字與行為。
3. **唯讀帳號匯出 → 送卡片**：唯讀帳號不能寫入，所以匯出後自動 `_draftPush('qsend', …)`，Lotion 在 AI 草稿看到「陳軒匯出了 115102501（未稅 …）要封存嗎？」，套用＝封存。
4. **健檢抓漏**（前端 `_healthRows` 35388 加一項＋雲端 `functions/ops/health.js`）：
   - 「匯出過、沒封存、內容已改掉」：`sendLog` 有 mode=only／reader 的紀錄，簽章不等於任何正式版也不等於現行 → 列出，點進去開第 3 節同一張「補登版次」卡片（補登工具因此變成通用功能，不只這一次用）。
   - 「已得標，合約金額對不上任何正式版次或現行報價的含稅總計」→ 抓 G6（在 FJ 以外送出的版本）。
5. 修正 G7 的說明文字（或補回存檔時的自動存檔，二選一，另案）。
