- 用 **擁有者帳號 jhchen0911@gmail.com** 操作。
- 電腦要先裝好 Firebase 工具（`firebase login` 做過）。沒做過的話，先照 `docs/Storage權限_部署步驟.md` 的「步驟一」裝，約 10 分鐘，**不算在這 15 分鐘內**。

## 第 0 步：換一把新的 AI 金鑰（3 分鐘，建議現在就做，不用等回國）

舊版系統曾把「智慧辨識 API Key」存在雲端參數裡，所有員工和唯讀帳號的裝置都可能有一份。v6.0.108 起系統不再同步這把金鑰，但已經流出去的要作廢才安全。

1. 登入 AI 服務後台（Anthropic Console：https://console.anthropic.com → 左邊 **API Keys**）。
2. 找到 FJ 系統用的那把金鑰 → 按 **Delete**（或 Disable）。
3. 按 **Create Key** 產生新金鑰 → 複製。
4. 新金鑰先存在 Lotion 自己的密碼管理器或記事本（不要傳給任何人、不要貼進 LINE 或 Email）。
5. **v6.0.118 起不用再把金鑰貼進網頁**：第 3 步會把它設成雲端密鑰，AI 辨識改由雲端代理呼叫，各裝置都不再保存金鑰。
   - v6.0.118 上線後網頁已經沒有金鑰欄位：要等第 3、4 步做完，AI 辨識才會恢復。

## 第 1 步：發布資料庫規則（2 分鐘）

這一步讓「AI 草稿」和「LINE 機器人設定」可以存進雲端，也一起加上 v6.0.118 的安全規則：
- 員工不能把自己升成管理員。
- 員工不能清空共用資料。
- 匯款帳號只有管理員能改。

**做之前先確認**：所有人的手機和電腦都已經重新整理到 **v6.0.118 以上**（標題列看得到版號）。還停在舊版的裝置，在規則發布後會上傳失敗（資料不會壞，重新整理到新版就好）。

1. 用瀏覽器打開 https://github.com/jhchen0911/FJ-system/blob/main/database.rules.json
2. 按右上角「複製」圖示（Copy raw file）。
3. 打開 Firebase 主控台 https://console.firebase.google.com → 專案 **jhchen-aed9a** → 左邊 **Realtime Database** → 上方 **規則** 分頁。
4. 把框裡的內容**全部刪掉**，貼上剛剛複製的內容 → 按 **發布**。
5. 看到「規則已發布」就完成。
6. 回到 FJ，**用 Lotion 平常用的那台電腦**（資料最新的那台）、Lotion 的帳號重新整理一次，等右上角同步完成。系統會自動把公司收款帳號和廠商匯款帳號「複製」到新的安全位置（舊資料不刪）。
7. 確認方式：
   - 開「參數設定」，看公司收款帳號是不是正確的那一組。
   - 開「客戶．廠商」，逐一點有匯款帳號的廠商 →「編輯」，帳號都對。
   - 有不對的，直接在這台電腦改正、儲存（會留變更紀錄）。
   - 用員工帳號開同一個廠商，匯款帳號欄是灰色、不能改，就代表生效了。

> **萬一要退回**（規則發布後有人一直上傳失敗、又來不及處理）：
> 1. 打開 https://github.com/jhchen0911/FJ-system/blob/main/docs/database.rules.v6.0.117.json（批次 H 上線前的規則，已存一份在 repo）。
> 2. 照上面 2～5 步貼上、發布。
> 3. 匯款帳號的新位置可以留著不管，退回後系統會自動改用舊欄位。

## 第 2 步：發布 Storage 規則（2 分鐘）

這一步讓系統能顯示 LINE 傳來的照片（`line/` 資料夾，網頁只能看、不能改）。

0. 先把 Firebase 主控台 → **Storage** → **規則** 框裡**目前的內容整段複製**，貼到記事本存起來（萬一要退回就貼回去）。
1. 開 FJ 系統 → **人員管理** → 頁面下方「唯讀帳號（AI 助理）」卡 → **產生 Storage 規則** → **複製全文**。
2. Firebase 主控台 → 左邊 **Storage** → 上方 **規則** 分頁。
3. 框裡全部刪掉、貼上 → **發布**。

## 第 3 步：設定 LINE 的兩個密鑰（3 分鐘）

密鑰只輸入在 Lotion 的電腦終端機，不要傳給任何人，也不要貼進 LINE 或 Email。

1. 打開 LINE Developers：https://developers.line.biz/console/ → 選「陳軒｜AI 助理」(@817supkw) 那個 Channel。
2. 打開終端機，一行一行貼：
   - **第一次做**（電腦裡還沒有 FJ-system 資料夾）：
     ```
     git clone https://github.com/jhchen0911/FJ-system.git
     cd FJ-system
     ```
   - **以前下載過**：先用 `cd` 進到 FJ-system 資料夾，再貼：
     ```
     git pull
     ```
   - 兩種情況接著都貼這行（指定 Firebase 專案，不然後面會問你要用哪個專案）：
     ```
     firebase use jhchen-aed9a
     ```
3. 貼上這行、按 Enter：
   ```
   firebase functions:secrets:set LINE_CHANNEL_SECRET
   ```
   它會問 `Enter a value for LINE_CHANNEL_SECRET`。回到 LINE Developers → **Basic settings** 分頁 → 往下找 **Channel secret** → 複製 → 貼到終端機 → 按 Enter。
   - 貼上時畫面不會顯示字，這是正常的。
   - 若它問要不要啟用 Secret Manager API，輸入 `y`。
4. 再貼這行、按 Enter：
   ```
   firebase functions:secrets:set LINE_CHANNEL_ACCESS_TOKEN
   ```
   回到 LINE Developers → **Messaging API** 分頁 → 最下面 **Channel access token (long-lived)**。
   - 還沒有的話，按 **Issue** 產生。
   - 複製 → 貼到終端機 → 按 Enter。
5. 再貼這行、按 Enter，把第 0 步的 **新 AI 金鑰** 也設成雲端密鑰（AI 辨識改由雲端代理呼叫，網頁不再持有金鑰）：
   ```
   firebase functions:secrets:set ANTHROPIC_API_KEY
   ```
   出現 `Enter a value` 時貼上新金鑰 → Enter。
6. 三個都出現 `Created a new secret version` 就完成。

## 第 4 步：把程式放上 Firebase（5 分鐘，大部分是等待）

在同一個終端機、FJ-system 資料夾裡，一行一行貼：

```
cd functions
npm install
cd ..
firebase deploy --only functions
```

- 跑 2～5 分鐘，最後出現 **Deploy complete!** 就成功。
- 如果問要不要刪除某個舊的 function（delete … ?），輸入 `N`。
- 第一次部署排程程式時，會問要不要啟用 **Cloud Scheduler**（或 Eventarc、Pub/Sub 等）API，一律輸入 `y`。
- 出現 `Eventarc` 或 `permission denied` 而失敗：通常是剛啟用的權限還沒生效，**等 3～5 分鐘，再貼一次** `firebase deploy --only functions`。
- 畫面上會列出 `lineWebhook` 的網址，長得像 `https://asia-southeast1-jhchen-aed9a.cloudfunctions.net/lineWebhook`。**把這個網址複製起來**，第 5 步要用。
  - 沒看到的話：Firebase 主控台 → 左邊 **Functions** → 找 `lineWebhook` → 複製「觸發條件」那欄的網址。

> **部署完再做一件事**：開 FJ → **人員管理** → 唯讀帳號卡 → 按「重新同步附件權限」（只有擁有者帳號看得到這顆），讓雲端替現有的每個帳號補上權限標記；之後請大家重新登入一次。

> **部署後檢查（v6.0.118）**：
> - **AI 辨識**：用員工帳號開 FJ，到任一個「智慧辨識」（例如發票照片辨識）試一張。能辨識就代表雲端代理正常。顯示「AI 代理尚未部署」代表第 4 步還沒成功。
> - **每日備份**：隔天到 Firebase 主控台 → **Storage** → `fydata/backups/server/daily/`，看到當天日期的資料夾（裡面每個資料區一個 `.json`，另有 `_index.json` 記筆數）就代表正常。每天 03:15 自動備份，保留 30 天；每月 1 日另存 `monthly/`，保留 12 個月。
>
> **萬一要用伺服器備份還原**（一般不需要；系統內的「資料救援」是另一套）：
> 1. Storage → `fydata/backups/server/daily/<日期>/` → 下載要還原的檔，例如 `shared.json`。
> 2. 檔案裡的 `data` 就是當天那個資料區的完整內容。
> 3. Realtime Database → 對應節點（例如 `fydata/shared`）→ 右上「⋮」→ **匯入 JSON**。先把 `data` 的內容另存成一個檔再匯入，**會整個覆蓋該節點**，請先請工程師確認。

## 第 5 步：把網址貼到 LINE（2 分鐘）

1. LINE Developers →「陳軒｜AI 助理」→ **Messaging API** 分頁 → **Webhook settings**。
2. **Webhook URL** 按 Edit → 貼上第 4 步的網址 → **Update**。
3. 按 **Verify**，出現 **Success** 就對了。
   - 失敗的話，多半是第 3 步的 Channel secret 貼錯，重做第 3 步的第 3 小步，再重做第 4 步。
4. 打開 **Use webhook** 開關。
5. 同一頁 **Allow bot to join group chats** 按 Edit → 會跳到另一個網站「LINE Official Account Manager」→ 把「加入群組或多人聊天室」改成允許（要拉進工地群組）。
6. 同一頁 **Auto-reply messages**、**Greeting messages** 按 Edit → 一樣會跳到 LINE Official Account Manager → **關掉**，否則機器人會多回一句官方的罐頭訊息。

## 第 6 步：在 FJ 綁定擁有者與工地群組（1～2 分鐘）

1. 用 Lotion 自己的 LINE 傳任一句話給「陳軒｜AI 助理」，例如「你好」。
2. 開 FJ → **人員管理** → 頁面下方「LINE 機器人」卡 → 按 **重新整理**。
3. 「待確認的一對一帳號」會出現剛才那句 → 按 **設為擁有者** → 名字填 Lotion。
4. 按 **傳一則測試通知給擁有者**，幾秒內 LINE 收到「FJ 測試通知」就完成。
5. 工地群組：
   - 把機器人拉進工地群組，請群組裡任何人講一句話。
   - 回 FJ 按 **重新整理** → 「待綁定的群組」選對應的工程 → **綁定**。
   - 每個工地群組做一次。
6. （可選）展開「機器人固定句子」，改成 Lotion 定稿的說法 → **儲存固定句子**。

完成後：
- 每天 17:30 機器人會在群組問三句。
- 20:00 把回覆整理成「施工日報（LINE）」草稿。
- 隔天 08:00 提醒沒回的群組。
- 群組出現「裂、變形、湧砂、沉陷、傾斜」會立刻通知 Lotion（前面有「沒有／無／未／不」的不算，例如「沒有裂縫」）。
- 所有寫進 FJ 的內容都要在總覽「AI 草稿」按確認才生效。

## 第 6.5 步：人員進場資料的證件搬家（v6.0.118，5 分鐘）

身分證字號、生日、地址、緊急聯絡人和身分證／健保卡／體檢／藥檢影像，原本放在所有員工和唯讀帳號都讀得到的共用區。v6.0.118 起改放只有管理員讀得到的位置，共用區只留姓名、職稱、證照和到期日，身分證字號只顯示 `A12****789` 這種遮罩。

**做之前**：第 1 步的規則已發布、所有裝置都更新到 v6.0.118。另外先在 Lotion 的電腦按一次「備份還原 → 匯出全部資料」，存一份到電腦（這時伺服器每日備份可能還沒跑過第一次）。

1. 先記下現在的筆數：開 FJ →「人員進場資料」，數一下有幾位人員、其中幾位有填身分證字號。
2. 用 **Lotion 平常用的那台電腦**（人員資料最完整的那台）、Lotion 的帳號重新整理一次，**等 10 秒**、右上角同步完成。系統會把這台電腦上的證件資料搬到新位置，並把共用區的證件欄位清掉（這台電腦本機的資料不刪）。
   - 如果第 3 步數字不對，到「人員進場資料」任選一位按「儲存」，再等 10 秒重看。
3. 驗證筆數：
   - Firebase 主控台 → **Realtime Database** → 資料 → `fydata` → `workerSens`：數一下有幾筆，應該等於第 1 步「有填身分證字號或有證件影像」的人數。
   - 點開 `fydata/shared/workers` 任一位，裡面應該看不到 `idNo`、`birth`、`regAddr`，證件的 `du` 是空的。
4. 用**沒有**「人員進場資料」權限的員工帳號開「人員進場資料」：身分證字號顯示遮罩、證件影像不見，就代表生效了。這類員工新增或修改人員時，證件資料會直接送到管理員那邊，員工自己的裝置看得到自己剛輸入的。
5. 管理員、角色有勾「人員進場資料」頁的人、唯讀帳號，都看得到完整資料（Lotion 10/22 決定）。名單由管理員的裝置在同步人員名冊時自動更新，**改了角色權限後，管理員開一次 FJ 就會生效**。產生業主的「人員進場申請表」也要由這些人產生，才會有完整身分證字號。

> **萬一要還原**：
> - 共用區的證件欄位清掉了，但完整資料還在三個地方：`fydata/workerSens`、Lotion 那台電腦的本機、每日備份（`fydata/backups/server/daily/`）。
> - 要讓共用區恢復完整資料，**規則和程式都要退回**：網站退回 v6.0.117（請工程師處理），再到 Lotion 那台電腦的「人員進場資料」任一位按「儲存」，舊版就會把完整資料傳回共用區。只退規則不退程式時，v6.0.118 仍只上傳公開版。
> - 驗證要等所有裝置都更新到 v6.0.118 之後再做：還在舊版的裝置編輯人員時，會把完整資料寫回共用區。

## 第 9 步：改版第 0 步上線後的兩件事（約 5 分鐘）

改版第 0 步（v6.0.113）合併上線、**第 1 步的新規則也發布之後**才做：

1. **確認共用區的報價歷史已經沒有成本**：第 0 步起，報價版本歷史上傳共用區前會先拿掉成本、估算成本、毛利，完整的另存私密區。上線後 Lotion 用管理員帳號開一次正式站、等右上角同步完成，共用區的舊歷史就會被換成去敏感的版本（這是寫入正式資料，做之前先到「備份還原」按「匯出備份」存一份）。
   - 驗法：Firebase 主控台 → Realtime Database → 資料 → `fydata/shared/qHistory` 點開任一筆 → `snapshot` 底下找不到 `costs`。
2. **（可選）開啟「擋舊版裝置寫入」**：所有手機、電腦都重新整理到 v6.0.113 以上之後，主控台 → Realtime Database → 資料 → `fydata` 旁的 ＋ → 名稱 `minVer`、型別選「字串（string）」、值填 `v6.0.113`（不用加引號；v6.0.114 起多打引號也會自動去掉）→ 新增。之後還停在舊版的裝置會跳紅條、不上傳。要關掉就把 `minVer` 刪掉。
   - 注意：只有 v6.0.113 以後的版本看得懂這個設定；更舊的裝置（v6.0.112 以前）看不到紅條，也不會被擋，要等規則端一起擋（改版第 5 步）。
   - 所以第 1 小步的「共用區報價歷史去成本」要**所有裝置都重新整理到 v6.0.113 以後**才算數：還停在舊版的裝置存檔時，會把含成本的歷史再傳回共用區。上線當天請在 LINE 群組請大家把系統重新整理兩次。

## 附：讓 Claude 以後可以幫忙執行 `firebase deploy`（可選，Lotion 自己貼）

設好之後，Claude 在 Lotion 的電腦上跑 `firebase deploy` 時就不用每次按允許。
這只放行「部署」這一個指令。設定密鑰（`secrets:set`）**不在放行範圍**，仍要 Lotion 自己輸入。

1. 用文字編輯器打開 `~/.claude/settings.json`：
   - Mac：Finder 按 ⌘⇧G，輸入 `~/.claude/` 前往，打開 `settings.json`。
   - Windows：`C:\Users\你的帳號\.claude\settings.json`。
   - 檔案不存在就新增一個。
2. **檔案是空的或不存在**，整份貼上：
   ```json
   {
     "permissions": {
       "allow": [
         "Bash(firebase deploy:*)"
       ]
     }
   }
   ```
3. **已經有內容**：
   - 已有 `"allow": [ ... ]` 的話，在中括號裡最後一項後面加一個逗號，再加一行 `"Bash(firebase deploy:*)"`。
   - 有 `"permissions"` 但沒有 `"allow"` 的話，在 `"permissions": {` 的下一行加 `"allow": ["Bash(firebase deploy:*)"],`。
   - 完全沒有 `"permissions"` 的話，在最外層第一個 `{` 的下一行加 `"permissions": {"allow": ["Bash(firebase deploy:*)"]},`。
4. 存檔。

## 出問題時

| 狀況 | 原因／處理 |
|---|---|
| 發布規則後，某台裝置一直顯示「上傳失敗」 | 那台還在舊版：重新整理兩次到 v6.0.118 以上 |
| 員工刪掉某個集合的最後一筆（例如唯一一位客戶）時，跳出「要由管理員裝置同步」 | 新規則不讓一般帳號清空整個集合，請管理員在自己的裝置刪 |
| 員工刪掉的資料過一陣子又出現 | v6.0.118 起員工的刪除要等管理員的裝置同步一次才會生效；同一位員工一次刪超過 30 筆時，總覽會出現「刪除申請待確認」，要管理員按確認 |
| AI 辨識顯示「AI 代理尚未部署」或「次數已達上限」 | 第 3 步的 `ANTHROPIC_API_KEY` 或第 4 步還沒做；上限是每人每天 200 次（隔天自動重算） |
| 送 AI 草稿時顯示「雲端規則尚未開放草稿」 | 第 1 步還沒做或沒按發布 |
| LINE 照片在 FJ 顯示灰色方塊 | 第 2 步還沒做 |
| `firebase deploy` 出現 `secret … not found` 或要你輸入值 | 第 3 步沒做完，照它的提示貼上對應的值即可 |
| LINE Verify 失敗（401） | Channel secret 貼錯：重做第 3 步的第 3 小步，再重做第 4 步 |
| 傳訊息給機器人，FJ 卡片沒出現待確認 | Webhook 沒開（第 5 步第 4 小步），或網址貼錯 |
| 測試通知收不到 | Channel access token 錯或過期：重做第 3 步的第 4 小步（可重新 Issue），再重做第 4 步 |
