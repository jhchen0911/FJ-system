# 真實黃金樣本 (b)：電腦端操作說明（Lotion-HQ 執行）

> 改版需求書 v1.3.3「測試安全網／第 1 步」。真實數字只留在 Lotion 的電腦，FJ（雲端）只拿到工具和「通過／差異 N 筆＋類別」這一行。

## 一句話

把正式資料「凍結」成一份快照，先用目前上線的程式算出一份「標準答案」；之後每個改版分支上線前，用分支的程式把同一份快照再算一次，兩份逐元比對。

```
正式網站（唯讀帳號）──exportData()──▶ 快照.json（凍結，不再變）
                                         │
              ┌──────────────────────────┼──────────────────────────┐
              ▼                          ▼                          ▼
     main 的程式算一次           分支的程式算一次             deid.js 去識別化
       base.json                    branch.json              deid.json → 匯入測試專案
              └──────── compare.js ──────┘
                 「通過」或「差異 N 筆：每期請款含稅 3、…」
```

為什麼用凍結快照、不直接在正式網站上算：正式資料每天在變，今天和明天算出來不一樣，就分不出是「程式改了」還是「資料改了」。同一份快照、兩版程式，差異只可能來自程式。

## 檔案放哪裡

一律放 `%USERPROFILE%\FJ-golden\`（例如 `C:\Users\jhche\FJ-golden\`）：

- 不放 OneDrive：會同步上雲。
- 不放 my-agent：會被備份到 GitHub。
- 不放 FJ repo：repo 是公開的。

| 檔案 | 內容 | 可以給 AI 看嗎 |
|---|---|---|
| `snapshot-YYYYMMDD.json` | 全量備份（含真實案名、金額） | ❌ 不行 |
| `names.json` | 真實名稱清單（給真名檢查用） | ❌ 不行 |
| `deid-map.json` | 真名→代號對照表 | ❌ 不行 |
| `base.json`、`branch.json`、`deid-check.json` | 算出的數字（只有 id、沒有名字，但有真實金額） | ❌ 不行 |
| `deid.json` | 去識別化複本（代號＋真實金額），只匯入測試專案 | ❌ 不行 |
| compare.js／namecheck.js／deid.js 印出的那一行 | 「通過」「差異 N 筆＋類別」「出現 N 個名稱」 | ✅ 可以，只回報這一行 |

## 第一次準備（一次就好）

在 PowerShell 執行（FJ-deploy 是部署用的乾淨 clone）：

```powershell
mkdir $env:USERPROFILE\FJ-golden -Force
cd C:\Users\jhche\Agent\FJ-deploy
git pull origin main
npm install --no-audit --no-fund
npx playwright install chromium
```

## 步驟 1：匯出快照（AI Chrome，唯讀帳號）

1. 用 AI Chrome 開正式網站 https://jhchen0911.github.io/FJ-system/ ，用**陳軒（唯讀）**登入，等右上同步完成。
   - 唯讀帳號讀得到 shared＋private，但不能寫任何東西，所以這一步不會改到正式資料。
2. 按 F12 → Console，輸入 `exportData()` 後按 Enter（唯讀帳號的畫面上藏了匯出卡，所以從 Console 叫；這個函式只下載檔案、不寫雲端）。
3. 瀏覽器會下載 `豐有工程_全量備份_民國年月日.json`。把它搬到 `%USERPROFILE%\FJ-golden\`，改名成 `snapshot-YYYYMMDD.json`（西元日期）。
4. 這份就是凍結快照。改版期間都用同一份，不要重匯。

## 步驟 2：每個分支上線前比對（每次都重算基準）

陳軒會給分支名稱（例如 `claude/step2a-unwrap`）。基準每次都用「現在的 main」重算，不用舊的 base.json，因為 main 合併過別的批次後，基準也跟著變。

```powershell
$B = "claude/step2a-unwrap"          # ← 換成陳軒給的分支
$S = "snapshot-YYYYMMDD.json"         # ← 換成步驟 1 的快照檔名
$G = "$env:USERPROFILE\FJ-golden"
cd C:\Users\jhche\Agent\FJ-deploy
git pull origin main
git fetch origin $B
git worktree prune
if (Test-Path $G\code-branch) { git worktree remove --force $G\code-branch }
git worktree add --force $G\code-branch origin/$B
node tools/golden/run.js --snapshot $G\$S --out $G\base.json --names $G\names.json
node tools/golden/run.js --snapshot $G\$S --out $G\branch.json --root $G\code-branch
node tools/golden/compare.js $G\base.json $G\branch.json
node tools/golden/namecheck.js --names $G\names.json --repo $G\code-branch --base origin/main
git worktree remove --force $G\code-branch
```

- 兩次 `run.js` 各印一行「完成：程式 v6.0.NNN｜得標案 …」。第一行是 main 的版號，第二行是分支的版號。
  - 有「✗ 有 N 筆算到出錯」就停，把那一行告訴陳軒。
- `compare.js` 印「通過」或「差異 N 筆：每期請款含稅 3、專案毛利 1…」。
  - 2a 這種「只整理、不改數字」的分支必須是「通過」。
  - 2b、3b 這種「會改數字」的分支，差異的類別和筆數要和陳軒事先列的預期差異清單一致。
  - **3b**：比對完再加跑一行（`--branch` 那份就是上面分支算出的 branch.json）：
    `node tools/golden/expect3b.js --snapshot $G\$S --base $G\base.json --branch $G\branch.json`
    要印「符合預期：專案毛利 N 案、報價毛利淨利 M 張（理論值不符 0 筆）；股東報表年度：…；清單外 0 筆」。理論值不符或清單外不是 0 就不能上線，把那一行告訴陳軒。
  - 印「不通過：…」代表比對本身有問題（例如快照沒載完整），也要回報。
- `namecheck.js` 印「沒有出現」或「出現 N 個名稱、M 處」。出現就不能上線，請 FJ 把那些字刪掉。
  - 預設只查 3 個字以上的名字。人名多半 2～3 個字，想連 2 個字也查就加 `--min 2`，但比較容易誤報，例如撞到一般用詞。
  - PR 說明也要查時，先把 PR 說明貼成 `$G\pr.txt`，再加 `--extra $G\pr.txt`。
- 這幾行回報給陳軒就好。要知道是哪幾筆，可以加 `--detail`：它會多列 id 和欄位名，或檔案和行號，不印金額和名字。

## 步驟 3：去識別化複本，匯入測試專案

```powershell
$S = "snapshot-YYYYMMDD.json"
$G = "$env:USERPROFILE\FJ-golden"
cd C:\Users\jhche\Agent\FJ-deploy
git pull origin main
node tools/golden/deid.js --snapshot $G\$S --out $G\deid.json --map $G\deid-map.json
node tools/golden/run.js --snapshot $G\$S --out $G\base.json
node tools/golden/run.js --snapshot $G\deid.json --out $G\deid-check.json
node tools/golden/compare.js $G\base.json $G\deid-check.json --deid
```

- deid.js 會把案名、業主、廠商、聯絡人、人員、業務換成代號：工程P001、業主C001營造、廠商V001、人員H001。
  - 業主代號會保留「營造／建設」字尾，因為業主類型統計靠它判斷。
  - 系統用的固定字（例如「公司支出（自付）」）和工項、材料的品名不會換。
- 會拿掉：薪資、薪資單、零用金、操作紀錄、所有圖片（證件、簽名、照片）、合約條件卡全文、施工計畫書草稿與附件庫、工具存檔。
  - 角色權限、管理員清單也不帶，所以匯入時不會改到測試專案的權限。
- 會遮掉：電話、傳真、Email、身分證號、統編、銀行與帳號、戶名、地址、郵遞區號、緊急聯絡人、生日、血型、工地地點。
  - 手機、身分證、Email 只認前後沒有接英數字的完整一段，所以 id 裡剛好長得像的片段不會誤報（v6.0.126）。
- 會清空：所有網址與檔案路徑。照片、附件的檔名是使用者取的，可能帶姓名或身分證號，算錢也用不到。
- 金額、數量、日期、id 都不動。
- **先看 deid.js 那一行**：要是「殘留原名 0 個、疑似電話／身分證／Email 0 個 ✓」。
  - 有 ✗ 就停，不要匯入，把那一行告訴陳軒。PowerShell 不會自己停，後面幾行照樣會跑。
- 最後一行要印「通過」，代表去識別化沒有動到任何金額。
  - `--deid` 的意思：薪資拿掉了，股東報表年度裡的人事費、稅前、分潤可分配與已領這幾欄不比。

匯入測試專案（Lotion 或 Lotion-HQ 用**測試專案的管理員帳號**）：

1. 開 https://jhchen0911.github.io/FJ-system/test.html ，**確認右下角有紫色「測試環境」**。沒有就停下來，不要匯入。
2. 登入測試專案的管理員帳號 → 參數設定頁的「資料匯出 / 匯入」卡 → 選擇檔案匯入，選 `deid.json` → 確認匯入。
3. 匯入會整包換掉測試專案原本的報價、請款、應付等資料（參數也會帶入快照的設定，例如稅率）。匯入後，測試專案就有一份「代號＋真實金額」的資料，給之後各步驟手動驗收用。

> ⚠️ 絕對不要在正式網站（沒有紫色標示的 index.html）按匯入：會整包蓋掉正式資料。

## 回報格式（給陳軒）

```
【黃金樣本 (b)】快照 YYYYMMDD｜基準 v6.0.NNN
分支 claude/xxx：compare＝通過（或：差異 N 筆：類別…）；namecheck＝沒有出現
去識別化：殘留原名 0 個；金額比對 通過；已匯入測試專案（是／否）
```

## 改版第 5 步 5a 之後匯出的快照

全量備份拆成兩個檔：`豐有工程_全量備份_<日期>.json`（一般）和 `豐有工程_敏感資料備份_<日期>.json`（薪資名冊、薪資單、零用金、人員證件）。用新快照跑 `run.js` 時兩個都要給：

```
node tools/golden/run.js --snapshot $G\<一般備份>.json --sens $G\<敏感資料備份>.json --out $G\base.json
```

`--sens` 會先把敏感資料併回快照再匯入，新舊版程式算出來的股東報表年度數字才比得起來。舊的凍結快照（一個檔）照舊，不用加 `--sens`。
