## 要做的事（約 3 分鐘，用電腦）

1. 打開 GitHub 上的規則檔：https://github.com/jhchen0911/FJ-system/blob/main/database.rules.json
2. 按右上角「Copy raw file」（兩個方框疊在一起的圖示），整份複製。
3. 打開 Firebase 主控台：https://console.firebase.google.com/ → 選專案 **jhchen-aed9a**（正式）。
4. 左邊選單「建構（Build）」→「Realtime Database」→ 上方分頁「規則（Rules）」。
5. 在編輯框裡按 Ctrl＋A 全選、Delete 刪掉，再按 Ctrl＋V 貼上剛剛複製的內容。
6. 按右上角「發布（Publish）」。看到「規則已發布」就完成。
7. 測試專案也要同步（可晚點做）：回到 Firebase 主控台首頁 → 選 **fj-system-test** → 重複第 4～6 步。

## 限制（B1）

- 唯讀帳號（AI）讀得到的管理區項目改成「允許清單」：報價成本、應付、費用、成本歷史、單價庫、分潤、材料台帳、成交庫、付款帳本、付款稽核；**之後新增的管理區項目預設讀不到**，要用再加。
- 付款帳本（paidLog）與付款稽核（payAudit）跟應付一樣，含薪資類應付的付款紀錄。
- 廠商匯款帳號：v6.0.118 已搬到 fydata/bank；這版起管理員裝置上傳共用區時不再帶已搬過的帳號，**管理員開一次 FJ 並存檔／同步後**，共用區的舊帳號才會清掉。
- AI 帳號那台電腦裡以前下載過的薪資、人員證件、證件照片，新版第一次同步時會清掉。
- 不在這次範圍：雲端檔案（Storage）裡的付款單據、發票照片、LINE 檔案，唯讀帳號仍可讀。


應付（payables）是一整串清單，規則沒辦法只擋裡面的薪資類應付，所以 AI 還看得到「付給某人多少薪資」這種應付金額；看不到身分證、帳號、薪資明細。要連這個也擋，需要另外搬資料結構（B2），Lotion 11/03 決定不做。
