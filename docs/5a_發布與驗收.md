# 改版第 5 步 5a 第一批：發布與驗收（Lotion 電腦操作卡）

**一句話：規則貼上、雲端程式部署、按一次「立即跑一次」、做一次備份還原演練。順序：測試專案全部做完 → 正式專案 → 說「上線」。**

```
① 測試專案貼規則(3分) → ② 測試專案部署雲端程式(10分) → ③ test.html 按「立即跑一次」(3分)
→ ④ 備份還原演練(20分，另一份操作卡) → ⑤ 正式專案貼規則＋部署(10分) → ⑥ 說「5a 上線」
```

## 前置條件（11/04 補）
- **測試專案 fj-system-test 要是 Blaze 方案**（Cloud Functions 只能在 Blaze 部署；Spark 免費方案會在 cloudbuild API 失敗）。升級：https://console.firebase.google.com/project/fj-system-test/usage/details → 修改方案 → Blaze，選正式專案同一個帳單帳戶；再到 Google Cloud 主控台 › 帳單 › 預算與快訊 設一個小額預算提醒（例如每月 NT$100）。測試專案用量很小，正常落在免費額度內。
- 不升級的替代做法見本卡最後一節「測試專案不升級時」。

## ① 測試專案貼規則（約 3 分鐘）
1. 開 https://raw.githubusercontent.com/jhchen0911/FJ-system/claude/step5a-backend/database.rules.json → Ctrl+A、Ctrl+C。
2. 開 https://console.firebase.google.com/project/fj-system-test/database/fj-system-test-default-rtdb/rules → Ctrl+A、Ctrl+V → 發布。
   - 這次只新增 `fydata/todo`（雲端待辦）和 `fydata/health`（雲端健檢）兩個節點，網頁都不能寫。

## ② 測試專案部署雲端程式（約 10 分鐘，在 Lotion-HQ 電腦）
在 FJ-system 資料夾開終端機：
```
git fetch origin claude/step5a-backend
git checkout claude/step5a-backend
cd functions
npm install
cd ..
firebase deploy --only functions:dailyHealth,functions:healthRunNow,functions:trashPurge,functions:dailyServerBackup --project fj-system-test
```
- **只部署這 4 支**：測試專案沒有設 LINE、AI 的密鑰，整包部署會停下來問密鑰。這 4 支不用密鑰。
- 第一次部署會自動開 Cloud Scheduler 等 API，問「要不要開」都按 y。
- 部署前會自動印出「[copy-calc] 已複製 N 個計算檔」，這是正常的。
- 完成後終端機會列出 `dailyHealth`、`healthRunNow` 等函式。

## ③ test.html 按「立即跑一次」（約 3 分鐘）
1. 開 https://jhchen0911.github.io/FJ-system/test.html ，用管理員帳號登入。
   （test.html 要等 5a 合併上線後才有新畫面；合併前可以先略過這步，只在 Firebase 主控台 › Functions › 紀錄看 `dailyHealth` 隔天 06:40 有跑。）
2. 經營報表 › 其他報表 › 資料健檢 → 最上面「☁ 雲端每日健檢」卡 → 按「立即跑一次」。
3. 看到「雲端健檢完成」，卡片出現日期和每一項「✓ 一致」就成功；截圖給陳軒。

## ③-2 回收筒驗收（測試專案，約 5 分鐘＋隔天 1 分鐘）
1. test.html › 參數設定 › 系統 › 資料匯出卡 › 「回收筒」→ 保留天數改成 **1**。
2. 刪一張測試合約 → 回收筒看得到 → 按「還原」→ 合約回來了。
3. 再刪一張 → 隔天打開回收筒，那一筆已經清掉（雲端 trashPurge 03:45 也會清）。
4. 做完把天數改回 30。

## ③-3 敏感資料備份（約 2 分鐘）
- 參數設定 › 系統 › 「立即匯出」先下載一般備份，接著跳出視窗按「下載」再存「敏感資料備份」。兩個都收好；兩個檔都有公司內部資料（一般備份仍含應付、成本），敏感那份更不要傳給別人。

## ④ 備份還原演練（約 20 分鐘）
照 `docs/伺服器備份_還原演練.md`（只在測試專案做）。

## ⑤ 正式專案（約 10 分鐘）
1. 規則：同 ① 的檔案，貼到 https://console.firebase.google.com/project/jhchen-aed9a/database/jhchen-aed9a-default-rtdb/rules → 發布。
2. 雲端程式：
   ```
   firebase deploy --only functions:dailyHealth,functions:healthRunNow,functions:trashPurge --project jhchen-aed9a
   ```
   - 正式專案也只部署這 3 支新的（其他函式不動，避免順便更新到 LINE、AI 那幾支）。

## ⑥ 最後要說的話
> 「5a 上線」

## 上線後兩週（並行比對期）
- 每天早上 06:40 雲端自動健檢；資料健檢頁「雲端每日健檢」卡每一項都要「✓ 一致」。
- 正常的「不一致」：員工刪的專案在等管理員核准、這台剛改還沒同步、看不到應付的帳號不比應付兩項。
- 連續 2 週一致，前端那段健檢才關掉（另一批做）。

## 測試專案不升級時（替代驗收）
- ②③④ 跳過，改成：
  1. 正式專案照 ⑤ 部署 3 支新函式（它們只寫 `fydata/health`、`fydata/todo` 兩個新節點和回收筒，不改既有資料）。
  2. 5a 上線後，用正式網站 › 資料健檢 › 「立即跑一次」，看到每一項「✓ 一致」就算通過。
  3. 回收筒驗收改在正式網站刪一張**自己新建的測試客戶**再還原（不要用真的資料）。
  4. 還原演練改成「只檢查、不寫入」：下載正式專案最新一份伺服器備份，跑 `node tools/backup-restore-prep.js <備份資料夾>`，看得到每個節點的筆數就停，**不要執行它印出的 `firebase database:set`**。
- 缺點：沒有在測試專案真正寫回過一次，備份「能不能完整還原」要等測試專案升級後補做。
