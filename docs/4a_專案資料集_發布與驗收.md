# 改版第 4 步 4a 專案資料集：發布與驗收步驟

## Lotion 電腦操作卡（上線前，在電腦上一次做完，合計約 15 分鐘）

**一句話：備份 → 測試專案貼規則、試 3 筆 → 正式專案貼規則 → 說「上線」。Storage 規則這次不用動。**

```
① 備份(3分) → ② 測試專案貼規則(3分) → ③ 試3筆(6分) → ④ 正式專案貼規則(3分) → ⑤ 說「上線」
```

### ① 全量備份（約 3 分鐘）
1. 電腦開正式版 https://jhchen0911.github.io/FJ-system/ ，用管理員帳號（jhchen0911）登入。
2. 左側選單（手機是右下「更多」）點「參數設定」→ 上方分頁點「系統」。
3. 找到「全量備份」卡，按綠色「立即匯出」。
4. 檔案會存到電腦的「下載」資料夾，檔名是 `豐有工程_全量備份_1151103.json`（民國年月日）。
5. 確認成功（三個都要有）：
   - 畫面下方跳出「資料已匯出備份」
   - 按鈕下面變成綠字「✓ 上次備份：今天」
   - 「下載」資料夾裡有這個檔，大小不是 0 KB（正常是幾 MB）

### ② 測試專案貼規則（約 3 分鐘）
1. 開規則原始檔（整頁就是規則文字）：
   https://raw.githubusercontent.com/jhchen0911/FJ-system/claude/step4a-projects/database.rules.json
   → 按 Ctrl+A 全選、Ctrl+C 複製。
2. 開測試專案的規則頁：
   https://console.firebase.google.com/project/fj-system-test/database/fj-system-test-default-rtdb/rules
3. 點編輯框 → Ctrl+A 全選 → Ctrl+V 貼上 → 按上方「發布」。
4. 看到「已發布」（或沒有紅字錯誤）就完成。

### ③ 規則模擬器試 3 筆（只在測試專案做，約 6 分鐘）
在 ② 的同一頁，按編輯框上方的「規則遊樂場」（Rules Playground）。每一筆都照下面填，再按「執行」：

| 欄位 | 填什麼 |
| :-- | :-- |
| 模擬類型 | 設定（set） |
| 位置 | `/fydata/shared/projects/p_123` |
| 已驗證 | 打開；供應商選 Google；電子郵件填 `jhchen0911@gmail.com`（介面沒有電子郵件欄時，改選「自訂」，在權杖內容貼 `{"email":"jhchen0911@gmail.com"}`） |

三筆只換「資料」欄：

| 第幾筆 | 資料（整段貼上） | 應該看到 |
| :-- | :-- | :-- |
| 1 | `{"id":"p_123","qid":"123","no":"2026-001"}` | 綠色「允許」 |
| 2 | `{"id":"p_999","qid":"123","no":"2026-001"}` | 紅色「拒絕」（id 跟報價對不上） |
| 3 | `{"id":"p_123","qid":"123","no":"2026-001","amount":100}` | 紅色「拒絕」（專案不放金額） |

- 每一筆結果出來後截圖整個畫面（要看得到位置、資料和綠／紅結果），三張傳給陳軒。
- 第 1 筆如果也是紅色、而且寫到 `version` 或 `uploadedAt`：代表測試專案的共用區還是空的（沒有任何資料），不是規則錯。用測試版 https://jhchen0911.github.io/FJ-system/test.html 登入、隨便存一張報價後再試一次。

### ④ 正式專案貼規則（約 3 分鐘）
1. 同 ② 的第 1 步複製同一份規則。
2. 開正式專案的規則頁：
   https://console.firebase.google.com/project/jhchen-aed9a/database/jhchen-aed9a-default-rtdb/rules
3. Ctrl+A → Ctrl+V → 發布。正式專案**不用**再試模擬器。

### Storage 規則：這次不用動
送審文件上傳畫面到 7c 才有，4a 的程式完全不會讀寫 `projects/` 這個 Storage 位置，所以 Storage 規則延到 7c 跟畫面一起發布。現行正式版「人員管理 → 產生 Storage 規則」產生的版本沒有這一段是正常的，**不要**現在去產生或貼上。

### ⑤ 最後要說的話（約 10 秒）
在「Hi，陳軒」說：
> 「4a 規則已發布，上線」

上線後（約 1 分鐘）用管理員帳號在電腦開一次正式版、重新整理兩次，舊案就會編好案號。

---

**一句話：先發布兩份規則（測試專案 → 驗過 → 正式專案），再合併程式；程式上線後，開頁就會自動替每一個得標案（含已結案）建一筆專案，舊資料一筆都不動。**

```
規則先發布（Lotion）           程式後合併（Lotion 說「上線」）       驗收（Lotion-HQ）
RTDB：shared/projects  ──►  開頁 1.5 秒自動建檔        ──►  projects-check.js
（Storage 延到 7c）           （每個得標主報價一筆）           專案數＝得標案數、連結、雜湊
```

## 1. 發布規則（Lotion，在電腦上）

順序：**測試專案 `fj-system-test` 先**，驗過再發布正式專案 `jhchen-aed9a`。

1. 打開 Firebase 主控台 → 選專案 → Realtime Database → 規則。
2. 把 repo 分支 `claude/step4a-projects` 的 `database.rules.json` 整份貼上 → 發布。
   - 這次只**新增** `fydata/shared/projects` 一個節點，其他節點逐字沒變。
3. Storage 規則：**延到 7c**（送審文件畫面才用到）。repo 的 `storage.rules` 與產生器已含 `projects/{pid}/docs` 一段，7c 上線時用新版「人員管理 → 產生 Storage 規則」產生再發布。
4. 規則模擬器（RTDB 規則頁「規則遊樂場」）驗兩筆，截圖給陳軒：
   - ✅ 允許：寫入 `/fydata/shared/projects/p_123`，內容 `{"id":"p_123","qid":"123","no":"2026-001"}`（用員工帳號；不帶 no 也允許，員工裝置建的專案由管理員裝置補號）
   - ❌ 拒絕：寫入 `/fydata/shared/projects/p_123`，內容 `{"id":"p_999","qid":"123","no":"2026-001"}`（id 和報價對不上）
   - ❌ 拒絕：內容多一個 `"amount":100`（專案不放金額，未知欄位一律擋）

## 2. 合併程式（Lotion 說「上線」後由 FJ 對話做）

- 上線前：Lotion 用管理員帳號在正式版做一次「全量備份」（寫入動作，Lotion 同意）。
- 合併 main、版號取 main＋1、冒煙全過才推。

## 3. 驗收（Lotion-HQ，本機，不連雲端、不改正式資料）

用凍結的真實黃金樣本快照（`%USERPROFILE%\FJ-golden\`），一次跑 main 和 4a 兩版：

```
node tools/golden/projects-check.js --snapshot <快照.json> --base <main 程式資料夾> --root <4a 分支資料夾>
```

會印（只印筆數，不印案名、金額、id）：

| 檢查 | 通過條件 |
| :-- | :-- |
| 專案筆數＝得標主報價數（含已結案） | 兩個數字相同 |
| 已得標追加全部掛進主約的專案 | 追加數＝掛上數 |
| 每條連結都打得開 | 連不到 0 |
| 案號沒有重號、格式正確 | 0、0 |
| 舊資料集內容一致（報價、合約、請款單、應付、付款帳本、發票紀錄） | main 和 4a 的雜湊相同 |

另外照舊跑 `run.js`＋`compare.js`（金額逐元相同，4a 不改任何算錢的地方）。

## 4. 上線當天（Lotion-HQ 唯讀）

- 正式版開「經營報表 › 資料健檢」：「專案」類沒有警告（有「追加報價已得標、但主報價沒有得標」要逐筆看）。
- 工程專案頁每一案標題旁有「案號 年份-流水號」（案號只由管理員裝置編；上線後先用 Lotion 的管理員帳號開一次正式版，全部舊案就會編好號。員工裝置先開到的會暫時顯示「案號編號中」）。
- **案號只給內部看**：報價單、請款單、信封、合約書列印都**不會**出現案號，對外照用報價編號。

## 舊版相容

- 舊版程式（含 v6.0.111）讀到新資料：不認得 `projects`，直接略過；舊版上傳只送自己的欄位，不會刪掉 `projects`。
- 還原舊備份（沒有 projects）：保留現有專案，並依還原後的報價自動補建。
