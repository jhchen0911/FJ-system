# 改版第 4 步 4a 專案資料集：發布與驗收步驟

**一句話：先發布兩份規則（測試專案 → 驗過 → 正式專案），再合併程式；程式上線後，開頁就會自動替每一個得標案（含已結案）建一筆專案，舊資料一筆都不動。**

```
規則先發布（Lotion）           程式後合併（Lotion 說「上線」）       驗收（Lotion-HQ）
RTDB：shared/projects  ──►  開頁 1.5 秒自動建檔        ──►  projects-check.js
Storage：projects/…/docs     （每個得標主報價一筆）           專案數＝得標案數、連結、雜湊
```

## 1. 發布規則（Lotion，在電腦上）

順序：**測試專案 `fj-system-test` 先**，驗過再發布正式專案 `jhchen-aed9a`。

1. 打開 Firebase 主控台 → 選專案 → Realtime Database → 規則。
2. 把 repo 分支 `claude/step4a-projects` 的 `database.rules.json` 整份貼上 → 發布。
   - 這次只**新增** `fydata/shared/projects` 一個節點，其他節點逐字沒變。
3. Storage → 規則 → 用「人員管理 → 產生 Storage 規則」產生的版本貼上發布（這版已多了 `projects/{pid}/docs` 一段）。
   - 若用 repo 的 `storage.rules`，要先確認 functions 的權限標記已生效（見 `docs/Storage權限_部署步驟.md`）。
4. 規則模擬器（RTDB 規則頁「規則遊樂場」）驗兩筆，截圖給陳軒：
   - ✅ 允許：寫入 `/fydata/shared/projects/p_123`，內容 `{"id":"p_123","qid":"123","no":"2026-001"}`（用員工帳號）
   - ❌ 拒絕：寫入 `/fydata/shared/projects/p_123`，內容 `{"id":"p_999","qid":"123","no":"2026-001"}`（id 和報價對不上）
   - ❌ 拒絕：內容多一個 `"amount":100`（專案不放金額，未知欄位一律擋）

## 2. 合併程式（Lotion 說「上線」後由 FJ 對話做）

- 上線前：Lotion 用管理員帳號在正式版做一次「全量備份」（寫入動作，Lotion 同意）。
- 合併 main、版號取 main＋1、冒煙全過才推。

## 3. 驗收（Lotion-HQ，本機，不連雲端、不改正式資料）

用凍結的真實黃金樣本快照（`%USERPROFILE%\FJ-golden\`），一次跑 main 和 4a 兩版：

```
node tools/golden/projects-check.js --snapshot <快照.json> --base <main 程式資料夾> --root <4a 分支資料夾>
```

會印（只印筆數，不印案名、金額、id）：

| 檢查 | 通過條件 |
| :-- | :-- |
| 專案筆數＝得標主報價數（含已結案） | 兩個數字相同 |
| 已得標追加全部掛進主約的專案 | 追加數＝掛上數 |
| 每條連結都打得開 | 連不到 0 |
| 案號沒有重號、格式正確 | 0、0 |
| 舊資料集內容一致（報價、合約、請款單、應付、付款帳本、發票紀錄） | main 和 4a 的雜湊相同 |

另外照舊跑 `run.js`＋`compare.js`（金額逐元相同，4a 不改任何算錢的地方）。

## 4. 上線當天（Lotion-HQ 唯讀）

- 正式版開「經營報表 › 資料健檢」：「專案」類沒有警告（有「追加報價已得標、但主報價沒有得標」要逐筆看）。
- 工程專案頁每一案標題旁有「案號 年份-流水號」。
- **案號只給內部看**：報價單、請款單、信封、合約書列印都**不會**出現案號，對外照用報價編號。

## 舊版相容

- 舊版程式（含 v6.0.111）讀到新資料：不認得 `projects`，直接略過；舊版上傳只送自己的欄位，不會刪掉 `projects`。
- 還原舊備份（沒有 projects）：保留現有專案，並依還原後的報價自動補建。
